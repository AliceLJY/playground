# 骑楼擂台 · 规格

一页规格。实现、测试、截图都对照这一页；规格改了，验收条目跟着改。
v1（2026-10-20）：招式时长按 PINOC 片段逐帧截图量出的出手帧对齐（刺拳 0.45 s、上勾拳 1.35 s、前踢 0.45 s），映射写在 `src/main.js` 的 `MOVE_CLIP`。数值的唯一出处是 `src/core.js` 的 `FEEL` / `MOVES` / `KINDS` / `WAVES`，本页只写要点。

## 1. 一句话体验

傍晚的西关骑楼街，街坊摆了一台醒狮擂台。玩家扮粤剧武生「阿龙」，从街口一路打到擂台：先过早茶阿婆的拖鞋连环、包租公的葵扇肚撞，最后上台对付醒狮头。核心操作是**拳脚连段 + 看准起手翻滚**，打出连击数，攒满「锣鼓」进二阶段。一局 4–6 分钟。

参考：akokoi1「长安街斗」（PlayCanvas + PINOC 泼溅角色，2026-10-20 X 帖）。只借做法，不搬代码与素材。

## 2. 操作

| 动作 | 键鼠 | 触屏 |
|---|---|---|
| 移动 | WASD | 左下虚拟摇杆 |
| 拳（连段 3 下） | 左键 / J | 右下「拳」 |
| 脚（连段 2 下，回旋踢收尾） | 右键 / K | 右下「脚」 |
| 翻滚（带无敌时间） | 空格 | 右下「滚」 |
| 格挡（按住） | Q | 右下「挡」 |
| 锣鼓二阶段（满槽可用） | E | 右上锣图标亮起时点 |
| 视角 | 鼠标拖 / 滚轮远近 | 右半屏拖空白处 |

## 3. 手感数值

| 项 | 值 |
|---|---|
| 拳连段输入窗 | 上一拳收招后 0.35 s 内；按键提前 0.25 s 会被记住 |
| 命中判定 | 出手帧前后 0.06 s，前方 75° 扇形、半径 1.4 |
| 翻滚 | 0.5 s，无敌 0.05–0.35 s，位移 3.0 |
| 格挡 | 正面 120° 内减伤 80%，被打中加 15 架势，满 100 破防 1.0 s |
| 顿帧 | 普通命中 0.05 s，连段收尾 / 回旋踢 0.10 s |
| 锣鼓槽 | 每次命中 +4，被打 −6；满 100 可开二阶段 8 s：出手 ×1.3、伤害 ×1.5、锣鼓配乐加速 |
| 回血 | 每段打完回 30；输了从本段满血重来 |
| 受击硬直 | 阿婆每下都硬直；包租公 1.4 s 内只硬直一次；醒狮头只被重击（上勾拳、回旋踢）打出硬直，2.5 s 一次 |
| 同时出手上限 | 敌方出招中 ≤ 2，令牌间隔 ≥ 0.8 s |

## 5. 美术与构图

- 场景：低多边形骑楼街（拱廊、满洲窗、招牌、灯笼），程序化搭，不用外部模型；擂台为地面高度的红毯方台、四角桩、横幅。PINOC 另生成过一张骑楼街高斯场景（17.6 MB，存外接盘），太大且没对齐街道尺度，首版没用。
- 角色：PINOC 一图生成的高斯泼溅角色（`.vsplat`），用 `@viggle/splat-engine`（MIT）在 PlayCanvas 里蒙皮播放；角色图由 Codex 生成，原图存外接盘批次目录。
- 配色：主色骑楼米黄 `#E8D3A9`（sRGB），辅色青砖灰 `#5B6470`，强调色醒狮红 `#D7262E`、金 `#F2B230`；天空黄昏渐变 `#F6A96B → #3B3A6B`。
- 机位：第三人称肩后，玩家在画面水平中线、垂直 55–65% 处，屏占高 22–32%。

## 6. 性能预算

- 目标：桌面 Chrome 1080p 60 帧；手机（OPPO Find N6 展开）Chrome 30 帧以上。
- 同屏泼溅角色 ≤ 5；首屏下载 ≤ 25 MB（引擎约 4.4 MB 未压缩 + 角色 + 动作），超了先压角色。
- 非单文件：发布目录含 `index.html`、`assets/`；CI 打包后整目录拷贝。

## 7. 验收条目

| # | 条目 | 检查方式 | 阈值 |
|---|---|---|---|
| 1 | 无头自动驾驶能从第①场打通到第④场 | `tests/core.test.cjs`，精准档 3 个种子、手潮档 4 个种子 | 精准档一次通关、纯战斗模拟时长 1–5 分钟；手潮档重来 ≤ 3 次 |
| 2 | 拳连段只在输入窗内续上 | `tests/core.test.cjs` | 窗外按键不续段 |
| 3 | 翻滚无敌时间内不掉血 | 同上 | 0 伤害 |
| 4 | 敌方同时出招不超上限 | soak 中记录 | 每帧 ≤ 2 |
| 5 | 角色真的在动（不是 T 姿势） | 浏览器 `?view=hero` 截两帧，间隔 0.3 s | 角色区域像素差 > 3% |
| 6 | 构图：玩家位置与屏占 | `?view=hero` 截图读包围盒 | 见第 5 节 |

| 8 | 页面零报错 | 控制台 error | 0 条 |
| 9 | 桌面帧率 | `?view=stress`（擂台前 2 包租公 + 玩家）采 10 s | 中位数 ≥ 55 帧 |

固定机位：`?view=hero`（街口开局）、`?view=wide`（骑楼全景）、`?view=stress`（第③场混战）、`?view=boss`（擂台）。`?auto` 自动驾驶打，`&fast=4` 快进。钩子 `window.__qilou`（`info()`、`snapshot()`、`sim()`）。

## 可选练招：街口讨教（2026-11-03）

首次「开锣」进入「街口讨教 · 一分钟」，常显至少 44 px 的「跳过，直接上擂台」。完成或跳过写入 localStorage，之后开锣直接进正式擂台；未完成或存储不可用仍走首次，读写失败不报错。菜单讨教入口保留，四段流程及默认难度不变。主目标是挑战与学习防反，手机触屏或电脑键盘、静音也能看懂。只生成一位早茶阿婆，按住「挡」/ Q 连续有效格挡三掌，出现持续提示「借过喇」，松挡后按「脚」/ K 实际命中一次完成。满三掌后阿婆停手等还脚；提前拳脚、空踢都不能完成，也不能打死阿婆。挨掌只清零连挡数，保留受击反馈，不扣血、不重置角色或时间。复用原格挡朝向与阿婆出掌预警（提前 0.32 s），不另造输入或动作。

一轮限 60 s 活跃游戏时间（含顿帧；暂停不计时），目标三次格挡；这两项数值**待试玩校准**。超时可再练，成功给阿婆一句点评（复用现有对白「擂台开锣，借借路！」），两种结尾均可进入正式擂台或回标题；练招暂停页也可回标题。沿用原配色、机位和渲染预算，不加素材与依赖。

1. 正常标题进入，只出现一位阿婆；四个视口 390×664、320×568、844×340、1365×900 的入口、练招提示（含漏挡时动画中的文字）、结算按钮不出框，交互按钮至少 44 CSS px，中心可点。
2. 用实际键盘 Q/K 与原生触摸「挡/脚」完成三次有效格挡再命中一脚；Node 跨种子操作序列和浏览器均断言确实发生三次 blocked、一次完成，提前拳脚及空踢不算。
3. 真实漏挡样本先有计数再清零，仍为同一位阿婆、同一轮、满血；60 s 未完成显示重练，重练从 0/3 和新的一分钟开始。Node 与浏览器计时误差不超过一个模拟步。
4. 结尾进入正式擂台后为原街口四位阿婆、满血、无练招计数/计时/保持输入；回标题再开锣亦如此。暂停、失焦继续沿用上午的清输入保护。
5. 原 Node 与浏览器检查仍过；构建产物四个视口零页面错误，逐张看图，默认画质不锁定。真人手感、真手机与声音另待试玩。

复现：正常入口 → 街口讨教 → 挡三掌 → 松挡、脚 → 结算 → 进入正式擂台；失败分支先挡一掌再松手挨掌，或等待一分钟。`tools/practice-check.cjs <base-url> <out-dir>` 走实际输入，仅读钩子状态，不置位格挡。

## 2026-11-03 B1 输入回归

触屏格挡持续状态与单次拳脚输入分离。原生触摸持续按住「挡」时，在无受击的开场连取 12 次状态（60 ms 间隔），至少 10 次为 block；键盘 Q 同样进入 block。松开、取消、丢失指针捕获后解除，暂停清空按键、摇杆、镜头拖动和按钮保持状态。失焦／隐藏接入暂停，回来需主动继续，恢复后不沿用之前的移动或格挡输入。

手机开场显示「左下方拖动走位，右半屏拖动看方向，锣鼓满了再按锣」。保留原来的左下摇杆范围与点击推进对白；对白未点完时战斗时间不推进。暂停层有可点的继续按钮，控制按钮至少 44 CSS px。`tools/input-check.cjs` 用 `?intro=skip` 绕过首次分流并以真实输入，在 390×664、320×568、844×340、1365×900 检查上述行为、可点击性及零页面错误。

## 首次入口验收（2026-11-03）

`tools/entry-check.cjs <url> <out-dir>`：清空 localStorage，开始进入练习；点击可见且至少 44 px 的跳过按钮进入原玩法；跳过后刷新直接进入原玩法；菜单练习按钮仍可用。另验未完成刷新、存储读取拒绝、写入失败和 `?intro=skip`；参数只绕过首次分流，不写来访记录。四档视口为 390×664、320×568、844×340、1365×900，要求零页面错误、按钮完全可见且中心命中，提前出脚及挨掌重置时的提示字形不得与跳过按钮相交，截图逐张检查。通过真实输入完成练习后的持久化与刷新分支由原练习浏览器检查覆盖。默认画质、玩法规则与数值不变。
