# 齿轮返修 · 一页规格

## 1. 体验一句话

访客打开先看到一组转着的齿轮，咬合的地方红点闪成一片：这是 dsh（DeepSeek Harness）第一次写出来的版本，齿形公式里渐开线的方向写反了一个符号，两个轮子每一帧都在互相穿过去。点一下「返修后」，红点全没了：这是 dsh 自己返修后的版本。核心操作是切换版本，再用「A–B 特写」「C–D 特写」凑近看咬合处。要的感受是「原来一个符号能错成这样，而且看得见」，以及「它自己真的改对了」。

## 2. 美学与场地

- 主美学：感官（金属齿轮、近景咬合、红光）加叙事（同一个 bug 的前后）。辅：探索（拖拽转视角、凑近看）。
- 弧型，看一遍：验的是没看过的人看完能不能说出「原版哪里不对、返修后好在哪」，不套通关率。这一条还没有找人试过。
- 场地：手机竖屏和电脑横屏各占一半；页面没有声音，静音也完整；单手能够到的是底栏的机位和播放按钮，版本切换在顶栏右上；一次看一两分钟。

## 3. 来源与展示改动

两版齿形函数 `makeGearShape` 来自 dsh 的两份页面：第一次生成的版本（原版）和它自己返修后的最终版。函数体保留 dsh 原文，`tests/gear-profile.test.cjs` 逐字比对；唯一的机械改动是把 `THREE` 从全局变量改成第一个参数，让 Node 里也能用。齿轮参数（模数 0.9、齿宽 1.5、层间距 1.05、齿数 12/30/12/30、主动轮 1.4 rad/s）和两版的运动学原样不动。

为了展示做的改动，两版统一：

1. 合成一页，右上角「原版 / 返修后」切换；齿形、轴的朝向（原版的轴没转到齿轮的转轴方向，返修后转了）跟着版本走。
2. Three.js r160、OrbitControls、RoomEnvironment 从 CDN 改成读 `vendor/`。
3. 装配统一居中（dsh 返修版的做法）；竖屏整组转 90°；顶栏、底栏和说明页取代 dsh 的左上角说明面板。dsh 原版在手机竖屏下主动轮 A 出画、面板盖住上方，这是原版的已知问题，展示页里两版都用同一套构图，并写成了检查（验收 6）。
4. 加了穿模检测、红点与红光、三个固定机位、慢放、`window.__gearRepair` 钩子。

没有放的东西：评测时另做的一份「只翻符号」的修正版。它不是主角，只在 `tests/gear-profile.test.cjs` 里作为一条对照出现：只翻符号还不够，60 帧里仍有 9 帧轻微穿模，dsh 后加的齿根内收和 4% 侧隙不是多余的。

## 5. 构图

- 画面分三段：顶栏（版本切换和徽标）、安全区、底栏（读数、机位、控件）。机位按安全区算，不按整屏算；栏的实际高度由页面量出来：电脑 59 / 55 px，手机竖屏 84 / 130 px，手机横屏 43 / 43 px。
- 全景：沿 (9, 9, 58) 方向拉远，直到四个轮子的齿顶圆整个落进安全区、离边缘至少 22 px（检查里取 8 px 容差）。横屏横排，竖屏整组转 90° 竖排。
- 特写：啮合点（两个节圆相切处）在安全区正中，周围 11×11 个单位都在安全区里；方向 (1.6, 1.2, 10)，几乎正对，略带斜角看得出齿厚。竖屏下受宽度限制会比横屏更近。
- 红点浮在齿轮前表面外 0.14 个单位：交点（线条交叉）大，穿进对方的顶点小；啮合处有一团径向渐变的红光，亮度跟穿模点数走，最亮 0.9。
- 说明页夹在顶栏和底栏之间，不盖住它们。

## 6. 性能预算

- 目标：2020 年以后的手机 Safari / Chrome 和桌面 Chrome，桌面 60 fps，手机不低于 30 fps；像素比封顶 2。
- 每帧穿模检测（两对啮合，原版穿模点最多的最坏情况）：中位数 < 2 ms，第 95 百分位 < 5 ms。
- 每帧 JS 时间（检测加渲染提交）中位数 < 6 ms。
- draw call ≤ 40（`renderer.info.render.calls` 实测 12，返修后 11）。
- 测量场景：默认入口，原版，播放中，600 帧。

## 7. 固定机位与钩子

| URL | 状态 |
|---|---|
| `?version=original` / `?version=repaired` | 选版本，默认 original |
| `?view=hero` | 全景（默认） |
| `?view=mesh` | A–B 啮合处特写 |
| `?view=mesh-cd` | C–D 啮合处特写 |
| `&t=<秒>` | 暂停在模拟时刻 t（A 的转角 = 1.4 t），两版同一时刻可以前后对照；浏览器检查用 `t=0.2` |
| `&hl=0` / `&slow=1` | 不标红 / 慢放 0.2 倍 |

不带参数就是正常入口：原版、全景、播放。固定机位只设机位，不暂停；加 `t` 才暂停。

`window.__gearRepair`：`ready`、`state()`（版本、机位、是否播放、模拟时刻、四个轮子的转角、当前帧的穿模计数 `penetration`（A–B、C–D 各有 `crossings` 交点数、`inL`/`inR` 穿进对方的顶点数、`count` 合计）、两版的 60 帧结果 `cycle`、视口与顶栏底栏高度、相机位置）、`setVersion(v)`、`setView(name)`、`play()`、`pause()`、`seek(t)`、`measureCycle(version)`、`probe()`（四个轮子、啮合点、顶栏底栏在屏幕上的位置）、`analyze(spots)`（读画布像素）、`markerScreen()`、`drawStats()`、`legacyLayout()`（把机位和布局恢复成 dsh 原版的样子，只给检查校准用）。

## 8. 验收条目

1. 齿形保真：两版 `makeGearShape` 与 `involutePoint` 的函数体与 dsh 原文逐字相同。（Node，`tests/gear-profile.test.cjs`）
2. 齿形方向：用真实生成的齿廓量齿宽，原版齿顶处的宽度 > 1.3 倍基圆处，返修后齿顶处 < 0.7 倍基圆处，12 齿和 30 齿两个轮子都要满足。（Node）
3. 穿模检测校准：一个啮合周期（A 转一个齿距）取 60 帧，A–B 和 C–D 两对，原版 60/60 帧穿模（单帧最多 12 对边相交、121 个顶点穿入，与 dsh 记录的数字一致），返修后 0/60；同一检测对「中心距拉近 0.3 的返修后」报 60/60，对「分开 2.0 的原版」报 0。（Node）
4. 页面检测与参照实现一致：每帧用的快速检测对 dsh 的参照检测逐帧对账（均分 60 帧加 20 个随机帧，两版两对）；按页面真实运动在一分钟内随机取 400 个时刻，原版 400/400 穿模，返修后 0/400；传动比 6.25:1、相邻两轮反向、B 与 C 同轴同速。（Node，`tests/mesh-check.test.cjs`）
5. 版本切换：URL 参数和按钮都能切；切完 `state.version`、徽标、读数、红点数一致；原版两对啮合都有穿模点，返修后全是 0 且没有红点、没有红色像素；页面自己跑的 60 帧结果是 60 / 0；播放中连采 12 次，原版每次都穿、返修后每次都不穿；「标红」只管显示不管计数。（浏览器）
6. 构图：五种尺寸（1280×720、1920×1080、390×844、844×390、720×800）× 两版，全景下四个轮子的中心都在画面内、外缘整个在画面里、不被顶栏底栏压住；转屏后重新构图；顶栏、底栏里同一行相邻的元素间距 ≥ 8 px；说明页夹在两栏之间，「关闭」按钮不用滚动就够得到。校准：dsh 原版的机位与布局在手机竖屏下必须被「A 出画」那条报错；720 宽下最初的窄屏断点（< 700）必须被间距那条报错；说明页最初的居中写法必须被「盖住栏」那条报错。（Node 算机位并与 three.js 相机对照，浏览器用真实相机检查）
7. 特写：`?view=mesh`、`?view=mesh-cd` 的啮合点在安全区里，原版下视野内至少 20 个红点且啮合点周围有红色像素，返修后没有。（Node 算机位，浏览器读像素）
8. 发布干净：页面运行中除本目录文件外没有任何外部请求；发布文件里没有外部地址、网络请求 API、本机路径、内网地址、会话 id；vendor 与 three@0.160.0 逐字节相同；`README.md` 没有汉字。（Node `tests/publish.test.cjs` + 浏览器抓包）
9. 性能：每帧检测与每帧 JS 时间落在第 6 节的预算里。（Node 测检测，浏览器测整帧）
10. 开局 30 秒：从不带参数的正常入口进，自动开播；2 秒内徽标带出 60 帧结果、读数 > 0；齿轮在转；点「A–B 特写」后相机拉近、点「返修后」后读数归零、点「全景」后拉回、拖动能转视角。桌面和手机各录一遍，逐帧看。（浏览器，手动跑）
