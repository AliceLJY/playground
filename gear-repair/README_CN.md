# 齿轮返修

DeepSeek Harness（简称 dsh）是作者在自己的 Mac mini 上跑的一个 agent 外壳。它一次写出了一个 Three.js 齿轮页：A（12 齿）带动 B（30 齿），B 和 C（12 齿）同轴，C 再带动 D（30 齿），总减速比 6.25 : 1。传动比和初始相位都对，错的是齿形公式里的一个符号：渐开线的方向写反了，每个齿越往外越宽，齿顶比齿根还宽，相互咬合的两个轮子每一帧都在互相穿过去。

作者没有替它改。任务书里只写了症状（齿越往外越宽）、两种查法（二维齿廓相交、啮合处特写截图）和「问题出在齿形生成那部分」，具体错在哪、怎么改，让它自己找。dsh 交回了改好的页面和它自己的证据：一个齿周期取 60 帧，改前 60 帧全部重叠，改后 0 帧。

这一页把两个版本放在一起：一个按钮在原版和返修后之间切换，红点标出每一处两条齿廓线交叉、或一个轮子的顶点落进另一个轮子里的地方。

**[在线看](https://aliceljy.github.io/playground/gear-repair/)**

## 操作

- 右上角：「原版 / 返修后」。中间的徽标是当前版本的 60 帧检测结果：原版 60 帧全部穿模，返修后 0 帧。
- 底部：A–B、C–D 两处当前帧的穿模点数，三个机位按钮（全景、A–B 特写、C–D 特写），暂停、慢放（0.2 倍）、标红开关和一页简短说明。
- 鼠标拖动旋转、滚轮缩放、右键平移；手机单指转、双指缩放和平移。空格暂停。

## 两个版本的区别

| | 原版 | 返修后 |
|---|---|---|
| 齿形 | 渐开线方向写反：12 齿轮的齿顶宽 24.3 度、齿根 13.4 度（按生成出的齿廓实测） | 齿根 16.0 度、齿顶 5.1 度 |
| 齿根与间隙 | 没有 | 齿根内收，留 4% 侧隙 |
| 一个齿周期（60 帧）里的穿模 | 60 帧全穿，单帧最多 12 对边相交、121 个顶点落在对方里面 | 0 帧 |
| 轴 | 圆柱躺在 Y 方向，没有沿齿轮转轴 | 转到了齿轮转轴方向 |

三处齿形改动都是 dsh 的：渐开线方向的符号（一行加上依赖它的另外三行）、齿根内收过渡、4% 侧隙。只翻符号不够：同一个 60 帧检测下，只翻符号还剩 9 帧轻微重叠，所以后两处改动不是多余的。

## 这一页改了什么

两个 `makeGearShape` 函数是 dsh 的原文，一字不改（测试会逐字比对）。其余都是为了展示：

1. 两版合在一页，用按钮切换；齿形和轴的朝向跟着版本走。
2. Three.js r160、OrbitControls、RoomEnvironment 从 CDN 改成读 `vendor/`，页面不向外发任何请求。
3. 两版统一把装配居中，竖屏整组转 90°，镜头按顶栏和底栏之间的区域算。dsh 原版页面在手机竖屏下主动轮 A 会出画。
4. dsh 的穿模检测（60 帧、二维齿廓相交）改写成一份共用脚本：页面每帧用它画红点，测试也用它。
5. 加了固定机位、慢放和 `window.__gearRepair` 钩子。

## 固定机位

| URL | 状态 |
|---|---|
| `?version=original` 或 `?version=repaired` | 选版本，默认原版 |
| `?view=hero` / `?view=mesh` / `?view=mesh-cd` | 全景 / A–B 特写 / C–D 特写 |
| `&t=<秒>` | 暂停在模拟时刻 t，两版可以在同一时刻前后对照 |
| `&hl=0`、`&slow=1` | 不标红、慢放 |

不带参数就是正常入口：原版、全景、播放。

## 本地运行

```bash
cd gear-repair && python3 -m http.server 8972 --bind 127.0.0.1
```

打开 `http://127.0.0.1:8972/`。必须走 http，双击 `index.html` 会因为 ES module 被拦而加载不出来。测试：`node --test tests/*.test.cjs`。没有构建步骤，发布时原样拷贝 `index.html`、`src/` 和 `vendor/`。

## 谁会点开、AI 素材

- 谁会点开：好奇「一个符号写反了，看起来到底是什么样」的人，以及想知道 AI agent 只拿到症状、要自己把原因找出来时会怎么做的人。
- AI 素材清单：齿轮页代码由 dsh 生成并自行返修，两个齿形函数保持它写的原样；围绕它的展页（切换、穿模标记、机位、测试）由人与 AI 协作完成。没有 AI 生成的图片、模型或声音。
