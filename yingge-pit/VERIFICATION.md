2026-10-21，Mac mini（Apple 芯片），Google Chrome 156.0.8078.47 无头模式，Playwright 驱动。真手机没有试过，声音没有人听过。

## 怎么复跑

```bash
cd yingge-pit
node --test tests/*.test.cjs
python3 -m http.server 8951 --bind 127.0.0.1 &
NODE_PATH="$(npm root -g)" node tools/browser-check.cjs check-out
NODE_PATH="$(npm root -g)" node tools/record.cjs out.mp4 --mode solo --seed 21     # 整局实录；--seconds 30 只录开局
```

浏览器检查与录屏需要本机已有 Playwright、Chrome 和 ffmpeg，本仓不安装它们；截图和 `report.json` 写进 `check-out/`（不进仓）。对线上复验：第二个参数换成 `https://aliceljy.github.io/playground/yingge-pit/index.html`。

## Node 测试（验收 1–7）

11 条全过（`node --test tests/*.test.cjs`，约 0.4 秒）。读数（真实模拟，单人 300 个种子）：

| 打法 | 胜率 | 第一波就输 | 平均时长 | p10 / p90 |
|---|---|---|---|---|
| 精准 | 100% | 0 | 44.9 s | 42 / 48 s |
| 手抖（单人） | 82% | 0 | 68.8 s | 54 / 83 s |
| 手抖（双人） | 99% | 0 | 60.8 s | 53 / 70 s |
| 不操作 | 0% | 100% | 8.4 s | — |
| 闭眼乱点 | 0% | 64% | 57.9 s | — |

测试本身用「已知是坏的版本」校准过：在临时副本里一次改坏一处规则，再跑测试。第一波窗口放宽到 1 秒、提前容差放到 0.3 秒、锣鼓槽改成 4 格、倒地改成 1.5 秒、打中降一整格、开场高度改成 4/5/6、大锣不看槽、会抽倒着的纸偶、中道分数都记给阿爸、铁枝不保证露出长度、第三波没有两道齐抽、漏一招只升半格，12 处改坏每一处都有测试变红。头一轮校准时「窗口放宽」和「提前容差」两处没被抓到，原因是测试拿 `core.js` 里的常量去比它自己；改成把 SPEC 第 4 节的数字直接写进测试后才抓到。

写测试时抓到并改掉的：

- 木偶在乐池最深处时，亮起的铁枝只露出 181 单位（规格要 200）。改成蓄力时铁枝至少伸出前板 200–240 单位。
- 双人模式里，心远的「点偏」会点到最左道。界面上本来点不到（左半边归阿爸），是自动试玩脚本的毛病；同时在规则里把「各管半边」写死：左道只认阿爸、右道只认心远。

## 浏览器检查（验收 6–10）

346 项全过，六种屏幕：手机 390×844（设备像素比 3，页面按 2 封顶，画布 780×1688）、竖屏 540×960（像素比 2，画布 1080×1920）、横屏 960×540、横屏手机 844×390、折叠屏 720×800、桌面 1280×720（像素比 1）。源码入口和按 `pages.yml` 拷出来的发布目录各跑一遍，结果相同。

- 开始页和八个固定机位在六种屏幕上都没有页面报错，没有向站外发请求，图片全部加载；戏台开口整个在屏内；按键全在屏内且不小于 44×44 css px；大锣在屏内、不压按键；双人时阿爸的键全在左半边、心远的全在右半边。
- 铁枝亮起看得清：在 hero、stress、duo 三个机位沿亮起的铁枝取 12 个画布像素，前板以上的点亮度全部 ≥ 200。同一方法量虚晃时没亮的铁枝，12 点里只有 1 点 ≥ 200，说明这个判据分得开亮和不亮。
- 字幕不压纸偶：逐帧扫四局完整对局（单人精准、单人手抖、双人手抖、双人精准，每 0.05 秒渲染一帧），竖屏、横屏各 4839 帧，其中 1879 帧有横幅、提示或木偶说话；字幕框与纸偶框零重叠。得分飘字出现在 1749 帧，碰到纸偶 0 帧。同一扫描里亮起的铁枝 680 帧，全部读到亮。
  - 同一扫描还查字幕之间互不重叠（横幅、提示、「大英歌！」大字、木偶说话），竖屏横屏都零重叠。
  - 头一次扫描抓到一处：纸偶被拍倒时绕脚底中点倒下，一半身子戳进乐池，压上木偶在池里说的「嘿嘿嘿」。改成绕外侧脚尖倒、压扁一点；又因为手臂卡片的透明角落仍伸到台板下 63 单位，把木偶说话的气泡往池子下方挪了 30 单位。
- 玩家默认档（不带参数、默认像素比）：手机、竖屏、横屏、桌面四种屏幕上，真实点开始页、等铁枝亮起后真实点那一道的按键（手机用触屏、桌面用鼠标），那一道都打中了。接着手抖档自动打 9 秒，绘制平均 0.24–0.41 毫秒、最长 0.6–0.8 毫秒，都是 60 帧。这是无头浏览器在台式机芯片上的读数，不能代表手机。
- 两个拇指同时按：竖屏和横屏的双人模式，用 CDP 在同一个触摸事件里放两个触点（阿爸·左、心远·右），两边在同一时刻各自生效，分别记给阿爸和心远。
- 屏幕中途变形：手机 390×844 双人开局后依次变成 844×390、720×800、390×844，布局在竖屏和横屏之间切换，戏台和按键都在屏内。

截图逐张读过，对照 SPEC 第 3 节：三个纸偶站在台板上的三条道；亮起的铁枝、台上光柱、按键发亮三处同时指向同一道；横幅在纸偶头顶以上，换场横幅在空乐池里，结算卡在纸偶脚下。

## 开局 30 秒

从正常入口（不带参数）进，用真实触屏在开始页点「双人」、再点开始，之后看铁枝亮起就点那一道的按键（反应 0.24 ± 0.06 秒），录了 30 秒逐帧看：选双人后按键立刻换成四块；第一招 2 秒后出现，袖子鼓起、铁枝发亮、纸偶出槌、火花落在双槌和铁枝相碰的地方、铁枝被打飞；锣鼓槽满时横幅提示、大锣发光；第一波打完木偶缩回乐池，换场横幅在空乐池里，红球从台面弹过；第二波横幅随后出现。读图后改了一处：火花原来落在胸口，出槌时双槌举在脸前，接触点上移到双手的高度。

## 整局实录

从正常入口用真实触屏打一整局（开始页 → 三波 → 台板盖上 → 画脸 → 「接棒」→ 结算卡），存在短片工程的 `game/` 目录（不进仓）。

- 第一条按 0.24 ± 0.06 秒反应：68.9 秒，赢，零失误，看不到纸偶被拍倒和木偶坏笑；抽帧读图还发现敲大锣那一刻，「锣鼓槽满了！点台口那面大锣」的旧横幅和「大英歌！」大字叠在一起。改成敲锣时清掉那条横幅，浏览器扫描加了「字幕之间互不重叠」，录屏工具的反应时间默认改按手抖档（0.30 ± 0.12 秒）。
- 第二条（`--seed 21`，手抖档反应）：79.3 秒，1080×1920、60 帧，H.264 High、yuv420p、bt709 tv，AAC 48 kHz 双声道；响度 −17.6 LUFS、LRA 9.1 LU、峰值 −0.4 dBFS。一局 64.6 秒打赢：出槌 32 次、妙 19、被拍倒 3 次、大英歌 4 次、牛肉丸 2 个。逐帧读过：被拍倒的纸偶歪倒冒星星，木偶被打中是叉叉眼，两道齐抽漏了两个时木偶眯眼大笑、池子里冒「再来呀」；横幅与大字不再叠。

## 没覆盖的

- 真手机上的触屏手感、两个人挤一台手机时拇指会不会互相挡、帧率。
- 声音：锣、梆子、甲子鼓点和木偶的笑都是合成的，没有人听过；静音时靠四层视觉预兆，开声时铁枝亮起有一声梆子。
- 好不好玩、好不好笑、虚晃和两道齐抽难不难，要真人试玩。手抖档是一个按正态分布出手的模型，不是真人。
