```bash
cd handwritten-board
node --test tests/*.test.cjs
python3 -m http.server 8973 --bind 127.0.0.1 &
NODE_PATH="$(npm root -g)" node tools/browser-check.cjs check-out
```

浏览器检查需要本机已有 Playwright 和 Chrome，本仓不安装它们；截图和 `report.json` 写进 `check-out/`（不进仓）。`HB_QUICK=1` 只跑固定机位（桌面和手机两种尺寸，约 1 分钟），试改动或跑故意改坏的副本时用；`HB_DIR=<文件夹>` 让 Node 测试去测另一份拷贝。浏览器检查的第三个参数可以换成线上地址。完整一遍约 4 分钟。

## 过程中发现并改掉的问题

把原来的单文件播放器只改掉字体和 GSAP 的路径、加上固定机位和钩子，先照最终的检查跑了一遍，441 项里 61 项不过：

1. 没有 `<!doctype>`，页面在怪异模式里（15 项）；没有 viewport 标签，手机按 980 像素宽渲染再缩小（9 项）。补上。
2. 桌面 1280×720：画框固定 1180 宽，加上控件条比屏幕高，控件被挤出屏要滚动（3 项抓到画框出屏，6 项抓到控件出屏）。改成由 JS 按剩余空间算画框大小，屏高不超过 520 时藏掉说明行。
3. 手机竖屏：16:9 的板书只有 374 像素宽，字缩到约 13 px，正文放不到 15 px。加了第二种板书形状（竖版 720×740），按「字在屏幕上写得更大」自动选，窗口变形时重新选（6 项抓到形状不对）。
4. 触屏上控件只有 32 到 33 px 高，竖屏最窄；样式改成 44 px，检查阈值 40。
5. 浏览器自动请求 `/favicon.ico` 得到 404，控制台报错（1 项）。加了空的 data 图标。
6. 没有暂停/继续按钮、没有空格键，「点画面」在界面上没有对应的可见状态（5 项加 2 项）。加了按钮和空格。
7. 「翻页模式关掉后位置不丢」这条在每种屏幕都不过：不是页面的问题，是我的检查在跳到某个时刻后把播放暂停了，再去判「没暂停」。改检查，不改页面。

读截图和开场 30 秒时又发现两处，都是先把症状写成检查、确认它能抓到、再改：

8. page1、page2 两个固定机位里手还停在板上，盖住了第三行和第二行的字，「写完的样子」读不到字。写了「手已离开板面」的检查，修前 4 项（桌面、手机各两个机位）不过；改成每页写完后手先淡出，再停 0.3 秒，再翻页。
9. 翻页时旧页已经擦掉、新页已经淡入 97%，页码还是「1 / 2」，要到下一页标题开始写才变，滞后约 1.3 秒。写了「旧页擦掉后页码已是 2 / 2」的检查，修前读到「1 / 2」；改成页码随擦页一起变。

读字体细节时还有一处不是靠检查抓到的：原来的代码把空格画成不换行空格（U+00A0），我第一版子集没有带这个码位。对着原代码读到后补上，并让子集工具和 Node 测试都按页面真实画出的字符算（见上面「删掉 U+00A0」那一行：浏览器抓不到，所以这条只能靠 Node）。

## 没覆盖到的

- 真手机：触屏手感、帧率、发热、手的阴影（`drop-shadow` 滤镜每帧重绘）在低端机上的开销。
- Safari、Firefox：`clip-path` 动画、`100dvh`、`text-wrap: balance`、`touch-action` 都按标准写，没有实测。
- 非苹果设备：英文字母（SVG、TTS、PPT）会落到龙藏行书自带的英文字形，比苹果上的 Bradley Hand 小一些。我在 Chrome 里强行去掉 Bradley Hand 看过两页，字能读、没有溢出，但真的 Windows 和安卓没测。字体菜单里的另外四款是苹果系统字体，在别的设备上会灰掉，只剩龙藏行书一个选择。
- 页面翻页时旧页擦掉到新标题开写之间有约 0.7 秒空白纸面，是有意的「擦黑板」，但会不会让人以为卡住了，要真人看。
- 长卷模式末尾，第二页标题会贴近画框上沿（没有被切掉，检查过在框内）；这是「镜头跟笔」原来的行为。
- 屏幕阅读器：每个字是一个独立的 `<span>`，读出来会一个字一个字地读，没有处理。没有照顾「减少动态效果」的系统设置，页面一打开就自动播。
- 字体菜单判断「本机有没有这款字体」用的是画布像素对比；「没有」这个方向只用一个编出来的字体名模拟过，没有在真正缺那四款苹果字体的设备上验过。
- GSAP 许可文本是从 ScanCode LicenseDB 的镜像抄的，因为 2026-10-23 官网那一页显示的是维护公告；以官网为准。
- 看起来舒不舒服、手的样子好不好看、节奏快慢，自动检查判断不了，要真人看。

## 线上复验

2026-10-23 随提交 `99eeb22` 上线：CI 运行 39855733007 通过（本玩意的检查与发布拷贝步骤都成功）；线上发布的文件与本地逐字节相同（SHA-256 比对）。

第一次对线上地址跑 `tools/browser-check.cjs` 时有 15 项没过，全是「只请求了本页自己的文件」那一条：检查脚本默认页面放在网站根目录 `/`，线上实际在 `/playground/handwritten-board/` 下，路径前缀对不上，自家文件被当成了额外请求。失败清单里列出的确实全是本页自己的文件，页面没有问题。改法是让检查按页面所在目录换算相对路径（`basePath` / `rel`）：自家文件还原成相对路径，同目录下多出来的文件、别的目录的请求照样会被抓到（三种情况都用一行 node 核过）。改完本地与线上各重跑一遍，513 项都全过。
