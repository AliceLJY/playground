# 像素连连看

[English](README.md)

最普通的连连看，牌面换成了[像素办公室](../ai-office/)里的小人。点两张一样的，中间能用拐弯不超过两次的线连上（线可以绕到棋盘外面一圈）就消掉，全部消完过关。

- 五关，棋盘从 4×6 长到 6×8；第一关只有四个长得很不一样的人，往后一关关混进越来越像的，最后一关十三位全员上场，包括老板和 CC 这种衬衫颜色只差一点点的。
- 每关有倒计时、3 次提示、2 次洗牌；走到死局会自动帮你洗牌，不扣次数。
- 消掉一对时两个小人挥手或跳一下；过关大家在办公室里出来合影。
- 手机竖屏单手玩，一关一到三分钟，没有声音也不缺信息。

在线玩：<https://aliceljy.github.io/playground/pixel-match/>

## 小人从哪来

牌上的小人一笔都没有重画。`tools/sync-figures.cjs` 从 `ai-office/office.js` 和 `office-core.js` 里按原文截出画小人的那几行（站姿、挥手、十一种配饰、老板、无忧和无虑，还有跳一下和挥手的弹簧），生成 `src/figures.js`。办公室那边改了长相，重跑一遍脚本就跟上；没跟上的话测试会红。

## 像不像怎么量

两种小人各画在同一张牌上，数颜色差得一眼看得出（ΔE > 20）的像素面积。规格里定了两条线：任意两种在自己那关的牌上至少差 100 个 CSS 像素²；差不到 300 的两种不放进前两关。细节和每关名单见 [SPEC.md](SPEC.md)。

## 结构

- `src/figures.js` 小人（生成的，别手改）；`src/raster.js` 一个只认 `fillRect` 的小软光栅，让测试能在 Node 里读像素；`src/card.js` 牌面和像不像的读数；`src/core.js` 规则、出盘、死局洗牌、自动驾驶；`src/game.js` 画面、点选、关卡流程、合影。
- 二维画布，没有图片、字体和第三方库，没有构建步骤。
- 固定机位：`?view=hero`、`wide`、`match`、`photo`、`final`、`lost`；试玩钩子 `window.__PLAYTEST__`，调试钩子 `window.__pixelMatch`。

## 本地运行

```bash
python3 -m http.server 8765    # 在仓库根目录
```

打开 `http://127.0.0.1:8765/pixel-match/`。测试：在本目录 `node --test tests/*.test.cjs`。浏览器验收：`NODE_PATH="$(npm root -g)" node tools/browser-check.cjs http://127.0.0.1:8765/pixel-match/ <输出目录>`。

## 验证

Node 测试管规则、有解、死局洗牌、小人与办公室一致、像不像的读数、三档自动驾驶的时长；浏览器检查管机位、真实点击、多种手机视口的版式、真画布和软光栅逐像素一致、绘制耗时和开局逐帧。手感、各关时限松不松、好不好玩，要真人试玩。

## 谁会点开、AI 素材

- 谁会点开：随手想玩一局连连看的人，不需要知道这些小人是谁；认得像素办公室的人会多一层乐趣。
- AI 素材：没有生成图片或声音。小人是像素办公室里代码画的像素画（同样由人与 AI 协作写成），本玩意的代码也由人与 AI 协作完成。
