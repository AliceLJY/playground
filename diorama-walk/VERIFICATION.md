## 第四轮做了什么

| 部分 | 做法 |
|---|---|
| 摇杆（触摸） | 走路时手指落在屏幕左侧 45% → 那里出现浮动摇杆（底盘半径 60 css px，死区 10% 即 6 px）；推的方向相对视线（上 = 前进、右 = 右移），速度 = 1.3 m/s × 推的幅度；每一步按当时的朝向换算，所以边转头边推会跟着拐；松手立即停（0 s）；推摇杆不改朝向。一次只有一个摇杆 |
| 转头（触摸） | 其余的手指单指拖动：走路时转头，按屏宽归一（水平划满屏宽 = 180°，竖直同一比例，俯仰仍限 ±1.2 rad）；外面和「看整间店」里是绕着转，沿用第三轮的 0.006 rad/px |
| 两只手 | 摇杆那根手指永远不参与捏合；两根都不是摇杆的手指才算捏合（先按摇杆或先按转头都一样）。判定在 `core.js` 的 `createTouchPad`，页面只转发 pointer 事件 |
| 轻点 | 位移 < 8 px 且 < 300 ms、当时只有这一根手指：走路时走过去，「看整间店」里落回去；左右两边都算 |
| 三级缩放 | 新模式 `rising`（店里 → 整间店，1.0 s）、`room`、`landing`（整间店 → 店里，1.0 s），以及从整间店出去的 `exit`（1.2 s，屋顶在前 55% 里淡回）。站在店里或门洞里捏合 / 滚轮往后 → 整间店；店外捏合 → 直接出去；整间店里张开 / 滚轮往前 / 轻点 → 落回对准的地面；整间店里捏合 / 滚轮往后 → 出去；Esc 在店里和整间店里都直接出去（正在升或落时，等这一段走完立刻出去） |
| 整间店视角 | 绕店内地面中心的轨道：默认与竖直方向 0.6 rad（俯视 56°），可在 0.25–1.0 rad 之间拖；水平方向起始与人当时的朝向一致；距离按「地面四角和墙顶四角都在画面内、留 6%」解出；视场窄的一边 40°；雾 0.008、雨换回底座上方的那种、无移轴。这间店的屋顶、吊顶、灯板、吊顶网格不画；墙、招牌、暗房屋顶照旧 |
| 落点 | 屏幕点射线与地面求交：在这间店里 → 推离家具 0.35 m、留在店内；在另一间店的占地里 → 那间店门外 2.6 m；在室外 → 夹到人行道并推离实体。视高 1.6 m、视线放平、朝向沿用相机的水平朝向 |
| 惊吓 | E2–E4 只在走路时判定，整间店里不触发；E3 已经打开的门在升到整间店后仍按时间开、停、关完；E5 只在所有被揭开的屋顶都恢复后才放（从整间店出去、从店里出去都是），看不见与否计入屋顶 |
| 提示文字 | 外面：拖动转 · 张开放大走进去；店里：左边摇杆走 · 右边拖动转头 · 捏合看整间店；站在店外：…· 捏合出来；整间店：拖动绕着转 · 张开落回去 · 捏合回到外面（电脑版对应滚轮与 Esc） |
| 滚轮 | 外面照旧连续缩放；店里与整间店一格换一级，换级后滚轮要静止 250 ms 才再认（防触控板惯性一口气连跳两级） |
| 其他 | 新机位 `?view=room`（收银台旁捏合后的整间店）；钩子新增 `back()`、`escape()`、`landAt()`、`groundPoint()`、`roomRotate()`、`roofs()`、`pad()`，`info().drawnRoofs` 报实际画出的屋顶各部分 |

## 与规格的出入（需要拍板的放前面）

1. **【需拍板】居中的双指捏合，经常有一根手指落在左边 45% 里。** 按规格，左边落下的手指就是摇杆，摇杆不参与捏合，所以这时什么都不会发生：人在店里捏合，要两根手指都在右半边才行。原来第 8 条的捏合两指在 x 95 / 295（390 宽，中心在屏幕正中），这一轮已经不灵了，检查里改到了 x 210 / 370。可选：(a) 规则不变，提示里写「右边捏合」（建议，简单、不会误判）；(b) 两根手指在约 100 ms 内先后落下、都还没动时算捏合（代价：两个拇指几乎同时按下去一边走一边转，有可能被当成捏合）。
2. **【需拍板】整间店视角的具体参数是我定的。** 规格只写了「在店的上方斜着往下看、整间店地面完整落在画面里」。现在是：默认与竖直方向 0.6 rad，可拖范围 0.25–1.0 rad；地面和墙顶一起框进画面、留 6%；视场窄的一边 40°；雾很淡、雨在底座上方、无移轴；墙不透明，所以从某些角度靠近相机那面墙会挡住它后面一窄条地面（正面是玻璃，不挡）。竖屏里店只占屏高中间约三分之一。
3. 落点：对准这间店外面的地面，会落到人行道上（夹回可走范围）；对准另一间店，会落在那间店门外。规格写的是「落回对准的地面，夹到可走范围、避开实体」，另一间店那种情况是我按「落点永远在室外」的旧规则补的。
4. 「站在店里」按「在店里或门洞里（门线外 0.15 m 以内）」判断，和第一轮从店里退出时揭屋顶的规则一致。
5. Esc 在升起或落下途中按下：等这一段（1.0 s）走完立刻出去，不在半空中转向。
6. 滚轮一格换一级；换级之后滚轮要静止 250 ms 才会再认，防止触控板惯性一口气从店里跳到外面。
7. 摇杆松手即停（0 s，规格要求 ≤ 0.2 s），没有加减速；推的幅度与速度成正比（一半 = 一半速度）。摇杆只在走路时出现，外面和整间店里左边的手指就是普通拖动 / 捏合。
8. 外面和整间店里的单指拖动仍按第三轮的 0.006 rad/px，只有走路时的转头按屏宽归一。
9. 落下（整间店 → 店里）用 1.0 s，与升起一样；从整间店出去用 1.2 s，与从店里出去一样，规格只定了升起的 1.0 s。
10. 「E5 判断看不见要计入屋顶恢复」我做成了所有出法都要等屋顶完全恢复再放，包括从店里直接出去：H6 里「从店里出去」的放置高度从第三轮的 3.86 m 变成 6.68 m，仍是看不见时放的。
11. 新增机位 `?view=room`（规格的机位表里没有），用于截图和检查。

## 已知问题

- 第 1 条：居中捏合有一半概率落到摇杆区，在手机上很可能被当成「捏合没反应」。
- 整间店视角里靠近相机的不透明墙会挡住墙后一窄条地面；第 2 条里的参数都还没人看过实机效果。
- 左边 45% 摇杆区在手指按下之前没有任何提示，只靠底部文字。
- 有一份改坏的副本（整间店的位姿参与惊吓判定）测试抓不到，原因是等价变异，见上。

### 读图结论

截图在 `~/Downloads/sync-bridge/AI产出/2026-10-07-微缩景观走进去/灰盒截图/`，都打开看过。

- `hero`：和第二轮一样的整景，多了一个人影：便利店玻璃右端、贩卖机右边，一个比店内暗得多的竖条加圆头。模型尺度上很小，但认得出是个站着的人。`hero-figure-4x`（左：画出来的，右：去掉人影）：人影站在收银台远端（店员那一侧），面朝门，是蓝灰色的剪影（隔着 25% 的玻璃，所以不是纯黑），脚下是亮的地砖。
- `scare`：站在后场门前约 1.5 m、稍低头：左边是开到 80° 的深色门扇，门洞正中站着人影，头和肩膀压在后面那块暗冷光板上，剪影很清楚；门洞地面是暗的，门槛和店内地面齐平；没有雨。`phone-scare` 同一帧的竖屏，门洞占满画面，人影更大。
- `reveal`：退出后的模型视角（回到触发时拉近的位置）：店门左边玻璃后、紧贴玻璃站着人影，面朝街，在清晰带里；收银台后已经没人。`phone-reveal` 竖屏拉得更近，人影约 95 css px 高，非常明显。`reveal-figure-4x` 是放大对照。
- `h2-before-blackout` / `h2-removal-frame`：吸入刚开始，前一张店里亮着、人影在收银台后；后一张店里整片暗下去（招牌也暗了），玻璃里看不到店内，人影已经不在，外面路灯、斑马线照旧。
- `door`、`phone-landed`、`default-landed`：落地画面，透过玻璃能看到店后墙中间偏右多了一个半开的后场门洞。
- `inside`：收银台旁看冰柜，右边是 35° 半开的后场门和后面的暗房。
- `mid-aim-door`、`next`、`phone-hero`、`phone-inside`、`default-hero`、`hero-sign-6x`：和第二轮一致（hero 里多了人影；竖屏 hero 里人影只有十几个 css 像素，几乎看不出来）。

### 与规格的出入（需要拍板的放前面）

1. **【需拍板】E5 的黑场兜底。** 规格要求「店内对相机不可见的时刻」放人影。退出路径一开始就定了，所以实现是沿路径往前查过屋顶后第一个看不见的时刻；但面朝店退出时（站在马路对面，或像 reveal 机位那样退着走出门、面朝店），整条上升路上人影位置一直看得见，没有这样的时刻。这种情况下现在的做法是：过屋顶那一刻店内灯熄 0.35 s（和 E0 同样的手法），在黑场正中放。可选：(a) 接受黑场兜底（建议，理由是「店内一片黑」本身就是看不见，和 E0 一致）；(b) 这种出法不放人影（揭示就只在背对店出来时发生）；(c) 改退出镜头路径制造遮挡（会动到第 2 条的手感）。实测四种出法里两种走了兜底，包括 reveal 机位自己。
2. **【需拍板】E4 多了「离铰链 ≥ 1.3 m」。** 规格只写「走到后场门 1.6 m 以内且门在中间三分之一」。门扇 1.0 m、人半径 0.25 m，砰地关门要扫过铰链 1.25 m 以内，人站在那里会被门扇穿过。现在要求离铰链 ≥ 1.3 m，于是贴着铰链一侧（门洞左边）走近不会触发，要往门洞右前方站。另一条路是允许关门时把人推开（会动玩家位置，和「只抖画面」冲突）。
3. **【需拍板】后场门变大开的时机。** 规格只写「E3 之后」。现在是 E3 那扇门关回之后、后场门在视野外（同 E3 的判据）、且人不在门扇扫过范围时才变。在你眼前变或在你身边变都会穿帮或穿模。
4. **【需拍板】「店内对相机不可见」按人影位置判。** 实现是人影的 5 个采样点都不在视野里或被实体挡住（玻璃不算挡），不是整个店内都看不见。按字面的「整个店内」判，看不见的时刻会少得多，第 1 条的兜底会更常发生。
5. E3 等 E2 整段（逐段熄灭加 1.6 s 静默，共 2.08 s）结束后才可能触发；规格写「E2 之后」，没说是 E2 开始还是结束之后。
6. 门铃在两间店的门上都响（隔壁小店的门也是靠近就开的平移门）；规格写的是「自动门」。只要便利店响的话改一行。
7. 收银台挪近玻璃 0.8 m（z −3.8..−1.4 → −3.0..−0.6），后墙开了真门洞、后面一间不能进的暗房。规格只给了收银台尺寸、写了后场门「装饰，不能进」，两者都没冲突，但布局变了。
8. `horror()` 的 `figure` 仍只取 `'counter' | 'window' | null`；E4 门洞里的人影用另一个字段 `scare: true` 表示，没有加第四个值。
9. 「店内光」降到 3% 时招牌也一起暗（算店自己的灯）；规格只点名了店内光、冰柜、灯板。
10. 震动在门撞上那一刻（E4 后 0.37 s）调用，和砰、高音、压暗、抖动同时。
11. 没发现协调消息和 SPEC 冲突的地方。

### 已知问题

- 竖屏 hero 里收银台后的人影只有约 13 css px 高，剪影对比 59.9%，刚好压在 60% 线上；在真手机上很可能注意不到。横屏 hero 是 39 css px、47.7%。
- reveal 的剪影对比 56.7%（竖屏 57.0%），离 60% 线不远：人影隔着 25% 不透明度的浅色玻璃，被提亮了。
- 砰的「4 倍」是计划增益。总线上有压限器（阈值 −8 dB、比 10:1），实际输出的峰值比会低于 4 倍，没有用离线渲染测。
- 声音在模拟时间走过事件时刻的那一帧播放，最多晚一帧（60 帧每秒约 17 ms），真机上没测。

### 没覆盖到的（需人试）

- **吓不吓人、节奏、强度：需人试。** 冰柜一段段灭的快慢、静默够不够长、没人开门停多久、门洞里露 0.25 s 够不够看清、砰的时机、出来看到玻璃后人影的感觉，自动检查只管「按规格发生了」。
- **声音听感：需人试。** 门铃像不像便利店门铃又不像任何品牌、嗡声是否烦人、砰够不够吓人、高音刺不刺耳、音量层级，都没有人听过；只验了计划增益和首次手势前不报错。
- **真机震动：需人试。** 只在桌面 Chrome 里用记录函数核对了调用和节奏；OPPO 上 Chrome 的 `navigator.vibrate` 实际震感没试，iOS 没有这个接口（已验证删掉接口时不报错）。
- 原有的手感、真机、Safari / Firefox、CI 未接入等未覆盖项同第二轮，仍然有效：灰盒只在分支上，`.github/workflows/pages.yml` 没接测试。
