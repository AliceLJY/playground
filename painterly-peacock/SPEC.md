# 油彩孔雀 · 制作规格

体验：暖象牙色的画面里站着一只油画质感的三维孔雀。访客移动鼠标领它走；鼠标停在它身上，它抖抖脑袋、尾屏一根根展开，移开后慢慢收拢；点一根尾羽，那根羽毛脱落飘到地上，孔雀走过去低头衔起，转头把它插回原来的插槽。滚轮往下它走近一步狠狠啄一下，往上退开；空格蹲下、起跳、落地。手机竖屏点地面领它走、点尾羽一样掉，底部四个按钮（开屏、走近、后退、跳）。声音默认关。场地是手机或电脑，看一两分钟，没有输赢。造型是示意，不对应真实品种，页面不写学名。

## 场景、配色与构图

- 舞台：地面 y = 0，孔雀能走的范围随屏幕比例变：桌面（宽高比 1.6）x ±1.12、z −0.9…0.75；手机竖屏（390×664）x ±0.24、z −0.55…0.45。尺寸是场景里的米，示意。
- 孔雀（`src/core.js` 定尺寸，`src/peacock.js` 造型）：身体是椭球（半轴 0.17 × 0.19 × 0.34，中心高 0.72），胸前一块深蓝绿，背上一圈小覆羽遮住尾羽根；脖子 7 节（每节 0.13，FABRIK 求解，从一条长度等于脖子的 S 形引导曲线起步，松的时候是平缓的 S 而不是折线）；头上有喙（长 0.16）、白色脸纹、黑眼睛、7 根冠羽；两条腿是两段 IK（大腿藏在羽毛里、画成深色短椭球，小腿细），脚四趾；两只翅膀平时贴身、跳跃时张开。
- 尾屏：26 根尾羽，每根有自己的 id、在身体上的锚点（插槽）、收拢方向和开屏方向。开屏按 `featherFan`：中间的先起、两边的后到，方向逐根插值，是真的几何运动，不是两张图交叉淡入。满屏时任意两个眼斑中心距 ≥ 眼斑直径（0.115）。
- 颜色全部是顶点色（sRGB 写、Three.js 转线性），不用 `instanceColor`。底色象牙 `#efe6d3`；羽色深蓝绿 `#0f4c4f` / `#0a3436`、胸 `#1b5f78`、脖子 `#165a6e`；尾羽羽片 `#17504a` 渐到 `#2f6450`、靠眼斑处掺一点暗金 `#8c6a26`；眼斑三圈：暗金 `#9a7a2c`、蓝绿 `#1d7f74`、深蓝 `#12305e`；翅膀褐色条纹。
- 油画感：每个材质在片元里用物体空间的拉长噪声把顶点色打散成笔触（随物体走，不在屏幕上游动），再加一层很细的屏幕颗粒；整幅画上再盖一层全屏的布纹、斑驳和暖色暗角（`paper`）。
- 色调映射用 Neutral（Khronos PBR Neutral），不用 ACES：ACES 会把深蓝绿和暗金压成灰。`tests/scene.test.cjs` 用同一条公式在 Node 里算过调色板在三档光照下的饱和度和色相。
- 光：一盏投影方向光（左前上方，暖白）、半球光（暖白 / 褐）、一盏右后方的冷色轮廓光。地面只是接影子的透明面加雾，画面就是那块象牙色。
- 每个网格带 `role`（`src/peacock.js` 的 `ROLES` 白名单，说明用途），没有无用途的件。
- 构图：相机由 `cameraFor(宽高比)` 二分求出，保证孔雀站在可走范围任何位置、任何朝向、开屏或收屏、跳到最高点，整只都在安全区里。安全区（屏幕 0…1，y 向下）：桌面 x 0.05–0.95、y 0.085–0.89；手机 x 0.04–0.96、y 0.13–0.84（上方让出标题和声音按钮，下方让出提示和四个按钮）。标题压在画面上（孔雀在文字后面），按钮不压孔雀。平时它侧身约 46° 站着，好让收拢的尾巴看得见；开屏时转向镜头。

## 动作和归属

四条通道各有一个主人，同一时刻只听一个：

| 通道 | 优先级（高 → 低） |
|---|---|
| 身体位置和朝向 | 拾羽 > 滚轮走近 / 后退 > 开屏展示 > 跟随鼠标 > 待机 |
| 脖子和头 | 拾羽 > 啄 > 盯着落下的羽毛 > 开屏抖头 > 静止 |
| 上下 | 跳（蹲 0.16 s → 空中 → 落地 0.3 s，落地有下沉和尾巴的弹簧回摆） |
| 尾巴 | 开屏量（鼠标悬停或手机「开屏」按钮锁定；每秒最多变 0.55） |

- 拾羽进行中：跟随鼠标、滚轮、跳、啄都不接（返回 false）；点同一根羽毛不理；点别的羽毛排队，最多排 3 根，再多的不理；队列里的一根一根接着拾。
- 拾羽分段：等羽毛落地 → 走到侧身能够到的位置（站点离羽根 0.72 m，优先侧对镜头）→ 低头 0.6 s → 衔住 0.18 s → 抬头 0.55 s → 转头 0.95 s → 插入 0.4 s（沿插槽方向滑进 0.14 m）→ 回正 0.5 s。
- 衔住那一刻，羽根相对喙尖的位置记下来，之后每一帧羽根都由喙尖加这个偏移算出，所以衔住到插入之间喙和羽根不会分开。插入结束那一帧，羽毛回到自己 id 的插槽，状态变回 attached。
- 掉落：羽毛从当前位置往侧面（从镜头看）和稍微朝镜头的方向飘下，落点限制在孔雀够得到、镜头看得到的范围；落地后羽片沿羽轴翻起约 29°（不完全平躺），从低机位也看得出是一根羽毛。

## 固定状态（URL：`?scene=名字`，从种子 7 真实玩到那一刻后暂停）

| 名字 | 内容 |
|---|---|
| `stand` | 收屏站立，侧身 |
| `display` | 满屏，面向镜头 |
| `fallen` | 第 16 根羽毛落地，孔雀正走过去 |
| `carrying` | 衔着第 16 根，转头往回插的半途 |
| `returned` | 插回之后 1.2 s，26 根都在 |

`window.__PLAYTEST__`：`ready`、`snapshot()`（位置、朝向、开屏量、当前动作、各通道主人、每根羽毛的 id / 状态 / 羽根和羽尖位置、屏幕包围盒、身体完整度读数、绘制次数、三角面数、渲染器字符串）、`reset()`、`setSeed(n)`、`step(ms)`、`hover(true/false/null)`、`walkTo(屏幕 x, y)`、`pluck(id)`、`jump()`、`peck(strong)`、`approach(±1)`、`setScene(名字)`、`featherAt(x, y)`。

## 预算（照实写）

- 三角面：16,951 个（`tests/scene.test.cjs` 在 Node 里按场景图逐个网格数，含实例数）。对象 14 个（孔雀 12 个网格，其中 7 个是实例化的；接影子的地面 1 个；全屏纸纹 1 个）。
- 绘制次数：估计每帧约 24 次（14 个对象 + 阴影那一遍 10 个投影件）。这是按场景图数的估计，没有在浏览器里读过 `renderer.info`。
- 帧率：没有测。写这一页的环境没有显卡，也起不了浏览器，帧率数字一个都没有，不作结论。
- 单文件约 595 KB（含 Three.js 0.186.1），预算 ≤ 1 MB。

## 截图和预览

- `tools/browser-check.cjs`：真实 Chrome 截 10 张固定状态图（5 个状态 × 桌面 1440×900、手机 390×664）加 `report.json`。**还没跑过**：写这一页的环境下载不了 Playwright 的浏览器（下载地址被网络策略拦截），也没有本地 Chrome。阈值是没跑过的第一版，第一次在真机上跑时可能要调。
- `tools/preview.cjs`：Node 里的 CPU 构图预览，用的是同一套场景图、同一个 `playScene` 和 `cameraFor`，平面着色，没有阴影、没有笔触噪声和颗粒、没有色调映射、没有页面文字。只能看构图、比例和遮挡，不是 WebGL 截图。首页封面 `covers/painterly-peacock.webp` 目前就是这个预览（满屏状态，4:3），等真显卡截图后应该换掉。

## 已知还没验证的

- 真显卡下的样子：笔触噪声的强弱、纸纹暗角、阴影、Neutral 色调映射后的实际颜色、轮廓光，全都没在屏幕上看过。
- 帧率、绘制次数的实测值、手机真机的触屏和发热。
- 声音只在代码里写了，没听过。
- 鼠标悬停判定用的是对整只孔雀的射线检测，离开后 0.35 s 才收屏；手感没试过。
