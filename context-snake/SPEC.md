# 上下文蛇 · 一页规格

## 1. 体验一句话

贪吃蛇，蛇头是小黑煤球，蛇身就是上下文。玩家用滑动或屏幕方向键带它吃文件、网页、日志，身子越吃越长，越长拐弯越慢；撞到自己叫「上下文污染」，这局结束。两个技能救命：**压缩**把尾巴（最老的那段上下文）一下砍掉一截，分数不扣；**派子 agent** 从尾巴甩出一截，让它自己去场上吃东西，回来只交一份很短的汇报，加分但不加长度。同时在外的子 agent 超过 3 个，再派一个，全部撞上 429 一起消失。

- 主美学：**挑战**（越长越难拐、要在压缩和分派之间做决定），辅美学：**叙事**（每个机制都对应一件真事，结算页点明）。
- 场地：陌生访客用手机竖屏、多半静音、单手或双手拇指，一局 1–3 分钟；电脑上用方向键 / WASD，Q 压缩、E 派子 agent。静音也要看得懂：所有事件都有文字和图形反馈，声音只是附加。
- 循环型：靠反复玩活着，验时长和通关率。

## 2. 规则（数值都在 `src/core.js` 的 `CFG`）

- 棋盘 13 列 × 17 行，四边相通（从一边出去从对边进来），只有撞到自己会输。
- 开局 3 段，向上走。每格用时从 0.17 秒线性降到 0.13 秒（两分钟内）。
- 一局是一次「会话」，120 秒；撑满算顺利结束，另加 100 分。
- 吃到：文件 +2 段 10 分，网页 +2 段 15 分，日志 +1 段 5 分。场上同时 3 个，每 40 秒多 1 个，最多 5 个；不刷在蛇身、子 agent 身上和蛇头 3 格以内。
- 对话本身也会长上下文：每 7 秒自动 +1 段「对话」。
- **新吃的挨着头，最老的在尾巴。**
- 转弯延迟：长度 ≤ 15 时按了立刻在下一格拐；之后每多 8 段，转弯要先多走 1 格才生效，最多 3 格（16–23 段慢 1 格，24–31 段慢 2 格，32 段以上慢 3 格）。场上用粉色虚线圈标出现在按方向会在哪一格拐，已排队的拐弯画成箭头。最多排 3 个拐弯；按反方向无效。
- 压缩：长度 ≥ 5 才能用，砍掉 `max(2, floor((长度−3)/2))` 段，尾巴剩一段「摘要」；不扣分；冷却 10 秒。
- 派子 agent：长度 ≥ 7 才能用，从尾巴取 4 段；冷却 1.5 秒。子 agent 每 0.2 秒走一格、穿过一切，去吃离它最近的东西，吃一个长一段、自己的「token」涨 3–5 万（只是示意），9 秒后回头找蛇头，挨到蛇头或回程满 5 秒就交汇报：+10 分 + 2 × 它吃到的东西的分值，**不加长度**，汇报字数在 205–588 之间。
- 429：已有 3 个在外时再派，第 4 个连同在外的 3 个一起消失，汇报全丢，派子 agent 锁 8 秒。
- 分数只因吃到、汇报、撑满会话而增加，从不减少。

## 4. 形象

小黑煤球照母版：黑色圆身、白描边、头顶细杆加粉色圆球、两只白色圆眼、一道短横嘴。**任何时候都有眼睛和嘴**，眼睛朝移动方向偏一点；标题页和结算页带两条细腿。子 agent 是小一号的煤球，天线球换成青色。全部用代码画，不用图片。

## 5. 构图（CSS 像素）

- 竖屏：下方操控区高为视口高的 26%（夹在 140–220），左方向键十字、右两个技能按钮；上方是顶栏（视口剩余高的 11%，夹在 54–78）加棋盘。横屏：操控区在右侧，宽为视口宽的 30%（夹在 220–340）。
- 棋盘格子取整，棋盘水平居中，完整在可视区内，不压顶栏也不压操控区；棋盘上的特效裁在棋盘内。
- 顶栏：左上分数，右上会话倒计时条和暂停按钮；第二行「上下文 N 段 · 转弯慢 N 格」和子 agent 三个槽。
- 方向键和技能按钮边长 ≥ 44 CSS 像素，按下（`pointerdown`）立刻生效，不等松手。

## 6. 性能预算与固定机位

- 目标：手机浏览器 390×664（像素比按 2 封顶）与桌面 1280×720，60 帧；二维画布，每帧绘制耗时平均 ≤ 4 毫秒、最长 ≤ 16 毫秒，测量场景是默认入口下精准档自动驾驶连跑 8 秒。
- 固定机位：真实对局推进到事件真的发生，再定格。

| 入口 | 状态 |
|---|---|
| `?view=hero` | 种子 3，精准档，跑到第 22 秒以后、至少 2 个子 agent 在外 |
| `?view=long` | 种子 1，手抖档，跑到长度 ≥ 17 且有排队的拐弯（转弯标记在画面里） |
| `?view=burst` | 种子 6，手抖档，跑到第一次 429 之后 0.25 秒 |
| `?view=end` | 种子 5，手抖档，跑到这局结束、结算页停 1.2 秒 |

可加 `&seed=` 换种子、`&t=` 改成跑到指定秒数。钩子：`window.__snake`（`ready`、`start(seed)`、`autopilot(level)`、`advance(秒)`、`freeze()`、`intent(名)`、`pause()`、`probe()`、`metrics`）和统一试玩钩子 `window.__PLAYTEST__`（`ready`、`snapshot()`、`reset()`、`setSeed(n)`、`step(ms)`）。不带参数就是正常游玩。

## 7. 验收条目

| # | 条目 | 检查方式 | 通过阈值 |
|---|---|---|---|
| 1 | 固定种子可重放 | `tests/core.test.cjs` | 同种子同打法两次结果完全相同 |
| 2 | 转弯延迟按长度生效 | 同上，真实对局里把蛇喂到各档长度后按方向 | 拐弯恰好在第 `延迟+1` 次移动时发生，各档都真测到 |
| 3 | 只有撞自己会输，穿边不会 | 同上 | 穿边 ≥ 1 次且不结束；撞身体时结束原因是 `pollution` |
| 4 | 压缩 | 同上 | 砍掉段数等于公式、分数不变、冷却内再按无效、尾巴是「摘要」 |
| 5 | 派子 agent 与汇报 | 同上 | 派出时身子少 4 段；汇报加分、不加长度，字数在 205–588 |
| 6 | 429 | 同上 | 第 4 个派出时 4 个全部消失、汇报不到账、锁 8 秒 |
| 7 | 刷新位置 | 同上，30 局 | 东西从不刷在身上、子 agent 上或蛇头 3 格以内 |
| 8 | 时长与难度 | 同上，种子 1–40，不操作 / 精准 / 手抖 / 莽撞四档 | 见下 |
| 9 | 技能真的有用 | 同上 | 同一手抖打法关掉两个技能后，平均存活时间比开着少 25% 以上 |
| 10 | 真实页面输入 | `tests/input.test.cjs` 在页面脚本上发真实事件 | 方向键、WASD、屏幕按钮、滑动走同一意图；暂停期间时间与长度不变；松手和触摸取消都结束滑动 |
| 11 | 手机视口与按钮 | `tools/browser-check.cjs`，390×664、320×568、412×700、844×390、1280×720 | 棋盘完整可见、不和顶栏或操控区重叠；所有按钮 ≥ 44 像素、完全在可视区、中心点到的是它自己 |
| 12 | 真实浏览器操作、报错与耗时 | 同上 | 真实滑动和真实按键都让蛇拐弯；四个机位都进入了声明的状态；零页面报错、不向站外请求；绘制耗时在第 6 节预算内 |

第 8 条的阈值（种子 1–40，都是真实模拟）：

- 不操作：没有一局能撑满两分钟（对话自己长上下文，直走迟早撞上自己），平均得分 ≤ 20。
- 精准档（会预判转弯延迟、勤用技能）：撑满率 ≥ 70%。
- 手抖档（80% 的时候记得转弯延迟、10% 的格子愣神一两格、3% 随手选一条不聪明的路、技能用得随缘、偶尔不看在外数量就派）：平均存活 45–110 秒；撑满和撞死都要出现（撑满 2–60%）；样本里真的发生过压缩、汇报和 429。
- 莽撞档（只追最近的东西、不看身子、不用技能）：每局都撞死，平均 30 秒内。

手感、拐弯延迟的数值、好不好玩，自动检查判断不了，要真人试玩。

## 8. 真事对照（结算页一句话）

- 撞过 429：作者有一次一口气派了 8 个重型子 agent，全撞上 429，最后只留下 3 份报告。
- 收过汇报：一次事实核查里，子 agent 在外面读到 14.4 万到 22.5 万 token，交回来的报告只有 205 到 588 个字（数字来自本仓 `dispatch-replay/` 的回放说明）。
- 没压缩就撞死：上下文快满时 Claude Code 也会把最老的对话压成摘要再接着干。
- 其他：上下文塞得越满越容易被自己绊倒，所以要压缩、要分派。
