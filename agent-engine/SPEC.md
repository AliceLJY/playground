# agent 引擎是什么 · 一页规格

## 1. 体验一句话

访客看一页六个镜头的动画讲解，弄懂一句话：模型 API 只会说话，让它动手、记事、转第二圈的那一层叫引擎，你每天改的 CLAUDE.md、skill、记忆库是引擎上面的 harness。六个镜头依次是：三层关系 → 只有 API 时卡在哪 → 加上循环后每一圈发生什么 → 循环外那 99%（八张失败卡，点开看引擎怎么接住）→ 三条路怎么选 →「有自己的日子」是在引擎外加一层世界状态。核心操作是看；步骤条、下一步和点失败卡翻面是可选的。要的感受是「原来循环那么小，围着它的东西那么多」。

页面里的循环、权限门、八种修复和世界状态闸都是 `src/core.js` 里真跑的迷你实现（脚本化的假模型 + 真循环），动画回放的是它的运行记录，不是手摆的动画。它们是教学用的小实现，不是 Claude Code 或任何产品的代码，页面上写明了这一点。

## 2. 美学与场地

- 主美学：叙事（一个问题一步步讲清），辅以发现（点开失败卡，翻面看引擎怎么接住）。
- 弧型，看一遍：验的是没看过的人看完能复述「模型自己不会动手；引擎是那段接住请求、执行、回填、再问的循环；循环只是一小部分，难的是转一千圈不出事」，不套通关率。
- 场地：手机竖屏与电脑横屏各占一半；页面不出声，静音就是全部体验；单手点按够用；一次看两到四分钟。读字多、读速因人而异，所以默认不自动播放：打开停在镜头 1 并播它的入场动画，翻页由访客自己点；想被带着走的人按「自动播放」，每个镜头按它的字数留停留时间（见第 5 节），再碰任何地方就交还给访客。
- 风格沿用原讲解页的「蓝图纸讲义」：浅色纸底、白卡片、细线框、等宽字做标签；跟随系统深浅色。

## 3. 配色（sRGB HEX）

| 用途 | 浅色 | 深色 |

| 引擎（身体）、焦点 | `#1D4ED8`，底 `#DCE6FB` | `#60A5FA`，底 `#16254A` |

## 4. 构图

- 页面宽度夹在 320–1040，居中；从上到下：标题与一句话 → 步骤条（六个按钮 + 播放）→ 舞台卡 → 上一步/下一步 → 底稿。舞台卡里一次只有一个镜头。
- 宽屏（舞台内宽 ≥ 760）：每个镜头左侧 1.2fr 放图，右侧 0.8fr 放文字；窄屏图在上、文字在下。
- 镜头 3 的循环：容器宽 ≥ 420 时是六站环形（站名卡 112 宽，中心写第几圈和当前阶段，右侧是 messages 数组），站与站、站与中心标签互不相交；窄于 420 时改成两列六格 + 顶上的当前阶段，不画环。
- 步骤按钮、播放按钮、上一步/下一步、失败卡的触控目标 ≥ 36 CSS 像素（宽和高）；文字最小 11 像素，手机上正文 ≥ 14。
- 失败卡的正反两面叠在同一格里，格子取两面中高的那个，所以翻面不推动版面；问题面底部有「点开：看引擎怎么接住 ↻」，接住面底部有「再点一下翻回去 ↻」。
- 上一步/下一步放在舞台下方，手机上读完一个长镜头不用滚回顶部；用它们（或步骤条、方向键）换镜头时，若页面顶部已滚出屏幕，就滚回步骤条。
- 所有会随动画出现的内容（对话气泡、messages 条目、判词、世界状态、翻面后的卡片背面）都先占好位置再显示，动画不推动版面。
- 页面不出现任何横向滚动；`overflow:hidden` 的容器不得裁掉文字。

## 5. 动效与节奏

- 全部用 CSS transition 和 `stroke-dashoffset`，不用画布；`prefers-reduced-motion` 下不播动画，直接显示每个镜头的终态，且不自动播放。
- 镜头 1：三层卡片 0.1 / 0.5 / 0.9 秒依次浮现（每张淡入 0.5 秒）。
- 镜头 2 对话：气泡 0.2 / 1.1 / 3.3 秒出现，红章 2.3 秒盖下。
- 镜头 3 循环：引擎真跑一遍，产生 15 个事件（3 圈：2 次工具、1 次纯文字收尾），每个事件 0.7 秒，约 10.5 秒播完。
- 镜头 6：模型提请求 → 规则闸给三个判词（驳回 / 改价 / 通过，间隔约 1 秒）→ 世界状态更新 → 转述，约 6 秒。
- 正常入口默认手动翻页：停在镜头 1，播它的入场动画，`mode` 是 `manual`，按钮写「自动播放」，进度条为空；没人碰页面就一直停在那里（验收 10 用假时钟等 45 秒验证）。这是 2026-10-23 从「默认自动播放」改回来的：自动播放每镜头上限 40 秒，而镜头 4 按 12 字/秒要约 77 秒才读得完，读者不碰屏幕时会被切走。
- 自动播放只在访客按「自动播放」之后开始：从当前镜头起，每个镜头停留 `clamp(动画时长 + 3 秒 + 可见字数 ÷ 12 秒, 12 秒, 40 秒)`，走完镜头 6 停下（按钮变「重新播放」），不循环。访客做任何事（点按任何地方、按键、滚轮、触摸滑动、步骤切换）都立刻停止自动播放（`mode` 变回 `manual`），按钮可以再开始。12 字/秒是扫读速度，上限 40 秒意味着字多的镜头（镜头 1、3、4、5、6 都顶到上限）按这个节奏读不完，所以它是「导览速度」，不保证读完；想细读就点一下。

## 6. 性能预算

- 目标：2020 年以后的手机 Safari / Chrome 与桌面 Chrome，60 帧；纯 DOM + CSS，没有画布和 WebGL，没有 draw call 可数。
- 纯静态，没有构建步骤，不发任何站外请求（字体用系统字体栈，没有库）。发布文件 `index.html` + `src/` 合计 ≤ 120 KB。
- 测量场景：桌面 1280×720 无头 Chrome，正常入口进入后点到镜头 3、看循环回放的 9 秒（全页面最忙的动画）。通过线：页面就绪（`window.__agentEngine.ready`）≤ 1.5 秒；没有超过 50 毫秒的长任务；`requestAnimationFrame` 的帧间隔中位数 ≤ 17 毫秒。无头 Chrome 的读数不代表手机。

## 7. 固定机位与钩子

固定机位用真运行的结果定格：`?view=N` 把页面带到第 N 个镜头并把该镜头的动画跑到终态（循环里的事件全部回放完、判词全部出齐），不自动播放，不用手摆的状态。不带参数就是正常入口（停在镜头 1 播入场动画，手动翻页）。

| 入口 | 状态 |
|---|---|
| `?view=1` | 三层：三层卡片全部出现、四张「谁在哪一层」卡 |
| `?view=2` | 只有 API：三个气泡与红章「没人执行 · 停在这里」全部出现 |
| `?view=3` | 加上循环：转完 3 圈，messages 里 7 条，阶段「停：模型不再要工具」 |
| `?view=4` | 那 99%：八张失败卡，全部是问题面；`&flip=all` 全翻到接住面，`&flip=1,6` 翻指定几张（从 1 数起） |
| `?view=5` | 三条路：三张路线卡，「借引擎」高亮 |
| `?view=6` | 有自己的日子：三个判词、世界状态更新、转述全部出现 |

钩子 `window.__agentEngine`：`ready`、`state()`（当前镜头、模式、是否定格、播放状态、各镜头的可见进度和翻面的卡）、`go(n)`（按 1 起的镜头号跳转，等同访客点击）、`settle()`（把当前镜头动画跑到终态）、`core`（`src/core.js` 的全部导出，供浏览器检查直接调用）。

## 8. 验收条目

| # | 条目 | 检查方式 | 通过阈值 |
|---|---|---|---|
| 1 | 循环真跑：同一份消息数组、同一个脚本化假模型，模型不再请求工具时才停；每个工具请求恰有一条结果；最终回答里的数量来自工具结果，不是写死的 | `tests/core.test.cjs` | 3 圈、7 条消息、配对零缺口；把目录换成 5 项，回答里的数量跟着变 |
| 2 | 没有引擎就停在请求上：同一个模型、同一句话，只调一次 API | 同上 | 消息数组末尾是工具请求、没有任何结果，到不了最终文字 |
| 3 | 八张失败卡对应八个迷你函数，坏输入给出预期修复，好输入原样放过（两侧都断言） | 同上 | 配对补 1 删 1 且之后零缺口；类型转换只改该改的键；压缩后在预算内且保留系统消息和最后一条；永久错误不重试、瞬时错误按退避重试到上限；危险命令被拒；未读先改被拒、读过放行；工具定义 token 大幅下降；XML 请求解析出同样的结构，畸形 XML 不崩 |
| 4 | 世界状态闸：同一串提案，驳回 / 改价 / 通过各一；终态由规则算出 | 同上 | 余额 782、在路上外套 10-24 到、今日午餐 98；被驳回的杭州不进状态也不进转述；改动提案 / 世界后结果跟着变 |
| 5 | 固定机位参数解析 | 同上 | `view=1..6` 解析正确，`0`、`7`、`abc` 回退正常入口，`flip` 只在合法范围内 |
| 6 | 自动播放（按钮开启后）的节奏：每个镜头停留按真实 HTML 字数算 | `tests/publish.test.cjs` | 每镜头 12–40 秒，全程 90–240 秒 |
