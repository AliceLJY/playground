# 像素办公室

一间可以放着看的 AI 团队办公室。11 位像素伙伴会打字、等人拍板、交活、休息和出差；送信员把纸条送到“小试AI”的桌前，再留在后墙公告板上。手机竖屏优先，电脑右侧显示团队面板。人物、桌椅、沙发和动画全部用 Canvas 2D 画，没有外部图片、字体、音乐或运行依赖。

本地服务读活动信号，网页只展示简要状态。没有服务时自动切换到约 400 秒循环的虚构演示，顶部明确标注“演示模式 · 模拟数据”。

## 怎么跑

在本目录执行：

```sh
node server/office-server.mjs
# 浏览器打开 http://127.0.0.1:3091/
node server/office-server.mjs --once
node --test tests/*.test.cjs
```

`--once` 读取已有状态，采集一次、向标准输出打印一份公开 JSON 后退出，**不写状态文件**，可以与服务同时验收而不覆盖公告板。持续服务只开一个。服务固定只监听 **127.0.0.1:3091**；没有安装常驻进程，也没有修改 launchd 或 Tailscale，后续由 owner 接。

真实配置和 token 已在本机准备好，位置是 `~/.config/ai-office/config.json`、`token`；状态与公告保存在同目录的 `state.json`。三个文件权限均为 `600`，目录为 `700`。不要复制进仓库。仓库中的 `config.example.json` 只有演示名单，来源均为 push 或送信员。

另起一台机器时，先复制并私下编辑配置，再生成 token；命令不会打印 token，也不会覆盖已有 token：

```sh
mkdir -p ~/.config/ai-office
chmod 700 ~/.config/ai-office
(umask 077; cp -n config.example.json ~/.config/ai-office/config.json)
test -f ~/.config/ai-office/token || (umask 077; openssl rand -hex 24 > ~/.config/ai-office/token)
chmod 600 ~/.config/ai-office/config.json ~/.config/ai-office/token
```

名单固定 11 个位置，顺序对应：总监、代码、双子一、双子二、创意、陪伴、探索、影像、写作、候补、送信员。每项包含 `id`、`name`、`role`、`color`（六位 HEX）、`source`；id 小写且不重复。老板是场景人物，不计入接口名单。配置或 token 修改后重启服务。

## 接口与小命令

| 接口 | 行为 |
| --- | --- |
| `GET /` | 网页 |
| `GET /api/state` | 公开只读：`{updatedAt, roster, notices, demo:false}` |
| `POST /api/report` | JSON：`{id, status, summary?}` |
| `POST /api/notice` | JSON：`{text}` |

两个写接口都要求 `Authorization: Bearer` 后接私有 token，并使用 `Content-Type: application/json`。token 不会交给网页。缺少或错误凭据返回 401，输入错误 400，请求体过大 413，类型错误 415，限流 429；保存成功返回 200 和 `{ok:true}`。

公开角色字段只有 `id,name,role,color,status,statusSince,badge`。状态为 `busy / waiting / done / idle / away / off / unknown`。每 10 秒采集；push 优先 10 分钟，重启仍有效；状态不变时保持原有 `statusSince`。公告按时间顺序保留最近 20 条。

```sh
bin/office-report builder busy "编程"
bin/office-report builder waiting "等一个决定"
bin/office-notice "有一份新的小进展。"
```

示例 id 要换成私有配置里的实际 id。两个命令自己读 token，静默、失败仍返回成功，不跟随跳转，最多等 5 秒。每个角色每 2 秒最多一条；公告和送信员共用限额；所有成功写入合计每滚动分钟最多 120 条。请求体总计最多 4096 字节，分块传输同样限制。

## 隐私与保存

- 网页收不到本机路径、进程参数、会话名、日志正文、pid 或任意任务摘要。摘要清理控制字符并截到 80 个 Unicode 码点，再归成笼统任务类型私下保存，不进入公开字段。
- 纸条只取**清理控制与格式字符后的首行前 80 个码点**，替换可识别的路径、链接、账号、疑似电话编号和金额，再限制到 80 个码点；占位符变短也不会把后文挤进来。规则清洗不等于理解所有隐私；调用方仍须提供不含真实姓名等私人信息的首行。
- 文本按文本插入，不当 HTML。静态服务只开放五个页面文件，不开放服务源码、配置、token、状态和测试；没有 CORS、统计或第三方请求。
- 状态串行写入，再原子替换。状态文件损坏会停止启动，保留原文件供修复，不会悄悄清空公告板。服务不打印凭据或原始来源错误。

## 名单与桌位

每个名单条目可以带一个 `desk` 桌位号（0 到 10，不重复；不写就按顺序）。可选的 `look`（0–11 整数）单独决定配饰，不写才沿用桌位。`courier` 是可选布尔值，最多一人是 true；这人负责送信，闲着守自己的桌。整份名单都没这个字段才兼容旧服务、退回 10 号桌；显式 false 不触发兜底。字段不合规整份快照拒收。同 ID 的桌位、外观、送信员标记变化会在下一次有效轮询生效。不满十一个人，空出来的桌子就空着。演示与示例配置里 Cobbler 坐 8 号、`look: 10` 保留邮差帽，豆包坐 10 号、`look: 8` 保留围巾；示例 source 保持原样，服务端给 courier 来源补 `courier: true`。2026-11-01 起 Kimi 的两路 TG bridge 合成一个座位（`instances` 多实例：任一在跑就算干活，全停才算下班）。

## 二期前端：附楼与今天

闲着的伙伴会到主房间左下角的游戏角：优先凑两人打乒乓，再安排双人下棋、两台街机、豆袋打盹或看书，满位后在旁边分开围观。Dots 的 9 号桌右移到 (229,269)，桌牌、奶茶和文件夹一起移过去，腾出的地方用来放乒乓台。单人去街机，凑够两人且都到场才开打。Cobbler 闲着仍守自己的工位（演示为 8 号）；奶茶仍按桌子大小摆，8 号照摆、10 号小前台不摆；交活后在工位庆祝并留下。按桌位号分配，状态不变就保留活动位，人数变化时只补空缺，具体规则见 [SPEC.md](SPEC.md)。

伙伴离开本人工位后，脚下会有浅底深字的小名牌，左边带本人的颜色块；字号为 7 逻辑像素。名字去空格和连字符后保留最多 8 个半角单位（非 ASCII 字符算 2 个），例如 GrokBot、etwincc。挤在一起时先错位，仍放不下就优先保留前景人物的牌子，不让文字互盖。招呼和道谢仍在头上；访客保持「客」，老板不加。在本人工位只保留桌牌。MV v7 同样使用现有身份、外观和名牌。

手机和窄窗口保持 360×740 逻辑像素的竖屏布局，上下滑动可看会议室（四张椅子、CC 投影位、六个后排站位）、两人旁听长凳、电话亭和储物间。开会时楼上亮起「开会中 ↓」。宽度 ≥1000 CSS px 且宽高比 ≥5/4 时，同一套模拟换成 **640×420 横屏平面图**：左边办公区，右边会议室、电话亭、储物间和累计木牌，整栋楼不用滚动。会议室门口改为亮灯。1455×782 下画布约 **1027×674 CSS px，1.605 倍**。跨断点时按当前状态重新就位；壁纸仍用竖屏主房间，MV 也固定为现有竖屏布局。合照随布局使用 720×1570 或 1280×930 像素，底栏不变。

后墙公告板只看数量：按北京日期统计今天纸条，钉 0–8 张便签，超过 8 张写 **+N**；最新纸条不足十分钟时，红图钉闪动。点或触摸公告板，本机打开手记的「公告板」看全文；访客打开「今天」，顶部说明纸条只在本人内网地址可见并显示今日数量。访客数量只取 `noticesToday`，缺字段不画便签，也不显示数量。送信员递纸条的大卡仍显示完整文本。累计木牌、今天栏的完整数字和当天最多 500 条结构化大事记照旧。

页面只消费两份状态快照的 `scene`、`stats`、`events`，缺字段显示空态；字段不合法整份拒收。不会用 busy 状态猜测开会或打电话。consult 顾问通话保持原优先级。一对一派活时，对方不是 away/off 且已经人在楼里，CC 就拿文件夹走到工位旁，放下、拍肩，说「这个交给你」，对方回「收到」，再回座；全程 6–10 秒，抽屉显示「递活中」。对方不在时仍进电话亭并飞文件夹。会议会打断派活；重复轮询不重播，status/statusSince 不改。保安必须同时有信号且处于北京 23–08 点才出现，每个巡逻时间戳只绕一圈。

## 来谈事

「探班」旁新增「来谈事」，只有四种固定来意：带项目来洽谈、来调研、来取经、随便聊聊。播放时从真正 idle 的伙伴中挑两位，随便聊聊只挑一位；送信员、真实开会或接电话的人不参与挑选。有活但没人空闲时由 Cobbler 在茶水位接待 20 秒；全员下班或离开时，门口告别 10 秒。只演画面，不调用 AI，也不修改真实状态。正常一拨含走路实测约 44–50 秒，轮流冒固定台词、握手、送客；真实会议优先，接待改去茶水位。

其他页面经原有 10 秒轮询看到来客，只接收两分钟内的新事件、按时间去重，一次一拨，待演队列最多三拨。握手合照只在发起页弹出。手机按钮放在可滚动房间上方，发起页跟随客人下楼、送客时回到楼上；壁纸来客期间临时显示附楼，不显示按钮或合照；MV 单独使用虚构信号。每轮演示第 34 秒自动来客，四种来意轮换；演示菜单点击只在本页播放。

`POST /guest/meet` 只接受 `{kind,v}`；kind 为 `pitch|research|learn|chat`，v 为随机 16–32 位十六进制标签，每个标签五分钟一次，并走全局限流。不接收 token、自由文字或身份信息。两份快照均含最近十条 `{kind,at}`、按来意统计的 `meetsToday`、`stats.meetsTotal` 与 `stats.today.meets`，事件类型为 `reception`。保留最近五十条事件，北京日分类计数另存，重启不丢。

`?view=reception` 使用种子 7，从零推进到第 49 秒。验证命令：`node --test tests/*.test.cjs`；浏览器检查：`NODE_PATH="$(npm root -g)" node tests/reception-browser.cjs`。截图和报告在 `tools/shots/reception*`，本轮实测、限制、owner 重启及公网复验见 [HANDOFF-reception.md](HANDOFF-reception.md)。

## 办公室里五件小事

五件事都由结构化信号触发，只演画面，不调用 AI，不改角色真实 status/statusSince。壁纸照常演，MV 明确关闭新演出。

| 小事 | 信号与画面 |
| --- | --- |
| 互审吵架 | 新一轮反驳至少一条，CC 和按会议起点、轮次稳定选出的 reviewer 到白板前争论，滚成漫画烟团，再叉腰回座。反驳至少三条时多一句、烟团更大。 |
| 交活请客 | 服务端看到连续 busy 至少 10 分钟转 done，同人每小时最多一次。拎袋子逐桌送小饼干，每份留五分钟。 |
| 吃瓜 | 有人等拍板、送信员正在递纸条或互审在争论，游戏角里 2–3 位 idle 伙伴捧像素西瓜凑过来，事情结束三秒后散回。 |
| 撞额度罚站 | 带 token 的额度报告让可让出的人到墙边面壁、举像素沙漏。到期、手动清除或服务端观察到转 busy 后解除。 |

优先表只定义在 `office-core.js` 一处：真实工作／通话／开会 > 罚站 > 接待 > 吵架＝安检门 > 请客／特产／雷达 > 吃瓜 > 游戏角。吵架属于本轮互审内部的动作，不另抢会议名额。每类同时一个演出、最多三个候场，超过两分钟未开演丢弃；罚站一旦开始按额度到期时间持续。访客时间向下取整到分钟，因此重播窗口最多提前 59 秒结束。

`POST /api/quota` 沿用 report 的 Bearer token。只收 `{id, minutes?, clear?}`：id 必须在名单内，minutes 为 1–300 整数、默认 60，`clear:true` 解除。非法字段 400，缺失或错误 token 401，限流 429。额度状态持久化，两份快照只列未过期的 `quota: {id: untilISO}`。小命令静默、失败仍返回成功、五秒硬超时：

```sh

bin/office-quota codex 90
bin/office-quota agy clear
```

## 当天手记、云上特产与选题雷达

手记保留当天最多 500 行；超过时先删最早的访客行，最后才删其它事件。北京换日清空前，原子写入 `history/YYYY-MM-DD.json`，含 `day`、完整保留的 `events`、`stats.today` 和只含状态的 `timeline`，目录 700、文件 600；写失败只记错误码，服务继续。默认放在私有 state 文件旁（正常为 `~/.config/ai-office/history`）；config 顶层 `historyDir` 可改目录。实时页面的“往日”标签可读最近十四份有效存档，详见下节。小黑板按 `stats.today.meetings` 写“今天开过 N 次会”，找到最近会议才加时间；旧快照没有 stats 时仍看事件。

- Grok Bot 的新一次 done 改演出差归来，每三小时最多一次，同次不再请客。背大包从门口走入，给 CC 放纸（十分钟），再给有人的桌子送白粉云朵棉花糖（五分钟），回座坐五秒，再从门口离开。正常状态源仍决定它何时回到 away，动画不修改状态。
- 豆包雷达只数当天 `YYYY-MM-DD |` 行，多处台账取较大值。config 顶层 `radarLedgers` 可覆盖，默认只读选题书架的副本 `~/Downloads/sync-bridge/选题书架/archive/ledger/radar.md`（书架每 2 小时从桌面拷一次）。不读桌面原件：launchd 下的 node 读 `~/Desktop` 不会报错，而是卡在隐私授权上，每轮采集都会多卡住一个读线程。读不到跳过；首次成功读取建立基数，增加才触发，落后的镜像不降低基数，北京换日归零。标题、链接和正文不进入状态文件或任一快照。
- 雷达归来戴转动天线，在后墙公告板贴“今日选题 N 条”；老板走过去说“有意思”。卡片当天保留，旧信号刷新只恢复卡片，不补演；豆包回座坐五秒再离开。真实工作、罚站和接待优先；老板被递信或等待拍板占用时最多等 25 秒。其它同事的祝词都是固定文本。

新字段：`scene.souvenir={at}`、`scene.radar={at,n,added}`，可为 null／缺省；统计 `souvenirsTotal`／`today.souvenirs`、`radarsTotal`／`today.radars`；事件 `souvenir {at}`、`radar {at,n,added}`。`n` 是当天累计，`added` 是这次新增；访客时间向下取整到分钟，不带任务文字。特产与雷达不加木牌行，安检门另有拦下计数。

每轮 400 秒演示在 185 秒安排特产、250 秒安排雷达（累计 13 条、新增 7 条）。`?view=souvenir` 从零推进到 200 秒；`?view=radar` 竖屏 266 秒、横屏 263 秒（走路距离不同），均在真实演出中定格。新验收：`NODE_PATH="$(npm root -g)" node tests/batch2-browser.cjs`，五张要求的图及交接见 [HANDOFF-batch2.md](HANDOFF-batch2.md)。

## 往日回放与防翻车安检门

实时本机页和 Pages 访客页的手记里有「往日」。选一天后，横幅显示日期、北京时间和 60×／240×／600× 倍速，默认 240×；可跳到下一条记录或退出。连续二十个回放分钟没有事件或状态变化，直接跳到下一条记录前一分钟。最后一条记录后一分钟停钟，让已经开始的演出走完。没有座位证据的人保持灰色问号；旧存档整天没时间线，会说明「这天只记了事件，座位状态没记」。回放期间实时快照暂存，退出立即应用最新一份；探班、来谈事和合照按钮隐藏，不发相应请求、不补欢迎或弹照片，访客心跳照常。演示、壁纸和 MV 没有入口，mini／历史接口不可达时隐藏标签。

状态归约只追加 `{at,id,s}`，s 限七个状态词；每次启动第一轮和北京换日第一轮另写全员快照。一天最多 3000 条，超过后停记并标 `timelineTruncated:true`，不删旧条。当天时间线随 state 保存，不进入两份实时快照；零点连事件和 today 统计一起存档。存档不能补回部署前没记的状态。

| 接口／字段 | 内容 |
| --- | --- |
| `GET /api/history` | `{days:[{day,events:n,timeline:n}]}`，最近十四份有效文件，新在前 |
| `GET /api/history/YYYY-MM-DD` | `{day,events,stats:{today},timeline}`，可带 timelineTruncated |
| `/guest/api/history…` | 同上，全部 at 向下取整到分钟；沿用 guest 限流，CORS 只放 Pages |
| `POST /api/gate` | Bearer 认证；只收 `{id,ok}`，id 在名单里，ok 必须是布尔 |
| `scene.gate` | `{at,id,ok,n}` 或 null，n 为本次合并拦截数 |
| `stats`／`stats.today` | gatesBlockedTotal、gatesPassedTotal／gatesBlocked、gatesPassed |
| `gate` 事件 | `{at,id,ok}`，固定模板写入「今天」和回放横幅 |

日期必须为真实的 YYYY-MM-DD 且在列表中。超 2 MiB、非法字段、路径穿越和坏文件一律只回 404，不回原文。前后端共用严格校验；按文件 mtime 等元数据缓存解析结果（含坏文件，最多 64 份）。公网仍用 `/office/api/history…`，不改 funnel。

```sh
bin/office-gate codex fail
bin/office-gate kimi pass
```

命令静默、失败仍返回成功、最多五秒。同 id 三十秒内额外 POST 回 200 但不入账。距该 id 上次新拦截事件不足两分钟的后续拦截，每次都增加累计与今日次数，只累加该次 n，不另起演出或新增事件行；绿灯单独计数。木牌多一行「安检门拦下 N 次」。缺这些字段的旧快照仍可用，存在但非法则整份拒收。

config 顶层 `makotoAudit` 可改审计路径，默认 `~/.claude/makoto_state/audit.jsonl`，null／空字符串禁用。启动从文件末尾开始，每轮最多新增 256 KiB；半行留到下轮，超长行跳过；文件变短或换 inode，重新从新文件末尾起。沿用十秒采集超时，只取 ts、event、exit_code：三种 live 事件的 exit 2 记 CC 被拦；exit 0 不演绿灯。findings／session_id／tool_name 等原文只在解析内存里，绝不写入 state、快照、事件、历史或日志。

伙伴先回自己座位拿文件夹，再走到 CC 旁的门：红灯「拦下！」／「拦下 ×n」，说「我再改改」后回座坐下；绿灯「放行」，继续把同款文件夹送到 CC 桌上再回座。门不阻挡寻路；真实工作／会议／电话／递信 > 罚站 > 接待 > 吵架＝安检门 > 请客／特产／雷达 > 吃瓜 > 游戏角。away/off/unknown 不演；不改 status/statusSince、不调用 AI。演示扩到 400 秒，旧事件时间不动，344 秒红灯、365 秒绿灯；`?view=gate` 从零真实推进至 347 秒红灯。两项都不进 MV。

检查命令：`node --test tests/*.test.cjs`、`NODE_PATH="$(npm root -g)" node tests/batch3-browser.cjs`。浏览器使用临时真实服务、假 history 和禁用的审计源，不访问正式服务。逐事件演法、旧档缺口、六张截图及实测见 [HANDOFF-batch3.md](HANDOFF-batch3.md)。没有新依赖或额外发布资产；正式 wrapper 收尾、重启和发布由 owner 接手。
