# 派活回放 · 一页规格

## 1. 体验一句话

访客看一段默认 90 秒的动画，回放一次真实的 Claude Code 工作：作者丢来一句任务，总调度把活拆开派给一群子 agent；每个子 agent 在自己独立的上下文里搜网页、读网页、写核查表，气泡越读越鼓；干完以后气泡被压成一个小包裹飞回来，里面只有几百字的报告。总调度收齐后写一份总结交还作者。要的感受是「原来 AI 是这样分工的」，以及「读了那么多，交回这么少」的那一下。

核心操作是看。可以暂停、拖时间轴、换播放速度，点一个子 agent 看它自己的数字。

## 2. 美学与场地

- 主美学：叙事（一件事从头到尾怎么被分掉、收回来），辅以感官（气泡鼓起、压扁、飞回）。
- 弧型，看一遍：验的是没看过的人看完能不能复述「总调度派活 → 子 agent 各读很多 → 只交回很少 → 总调度合成」，不验通关率。
- 场地：手机竖屏和电脑横屏各占一半；多半静音，页面不出声；一次看一到两分钟。静音也要看得懂，所以每个关键时刻配一句字幕。

## 3. 数据与隐私

- 数据来自作者本机的 Claude Code 会话记录，由 `tools/extract.py` 抽成 `data/<slug>.js`，页面只读这份。
- 抽出来的只有：任务标签（任务说明里的简短 description）、模型名、工具类别（网页 / 文件 / 写入 / 命令 / 外部工具 / 其他）、时间（相对开始的秒数）、token 数、字数。不带任何提示词原文、报告原文、文件路径、工具参数。
- 任务气泡里那句话与字幕都是手写的，不从会话里复制。
- 本仓公开，推上 main 即上线：测试里有一条断言扫数据文件，不得出现路径、链接、`.md` 文件名、tool id。

数据格式（`schema: 1`）：

| 字段 | 含义 |
|---|---|
| `duration` | 回放窗口长度，秒 |
| `task` | `{t, text}`：作者发任务的时刻与手写的一句话 |
| `main.ctx` / `main.tools` | 总调度每轮的上下文 token `[t, n]`；它自己的工具调用 `[t, 类别]` |
| `agents[]` | 每个被派出去的执行者：`id`、`label`、`kind`（`subagent` / `external`）、`vendor`（`claude` / `kimi` / `agy` / `grok` / `gpt`）、`family`（模型族）、`dispatchT`、`startT`、`endT`、`handbackT`、`promptChars`、`handbackChars`（它自己写的报告字数，不含系统外框）、`ctx`、`tools`、`peakTokens`、`toolCount` |
| `reply` | `{t, chars}`：总调度交还作者的那条回复 |
| `captions` | `[[t, 文字], …]`，文字里可用 `{peak:ID}` `{report:ID}` `{reply}` `{sumPeak}` `{sumReport}` `{n}` 占位，播放时按数据填 |

`kind: external` 的执行者（Kimi、Gemini、Grok 等外部 AI）在会话记录里看不到内部过程，`ctx` 可以为空：页面把它画成实心色块，只显示派出、交回和用时，不编气泡。

## 5. 构图

- 顶栏 56–64 px：左标题，右播放控制。底栏约 96 px：计数一行 + 时间轴。中间是舞台。
- 横屏（宽 ≥ 高）：作者在舞台左侧 8%，总调度在 26%，子 agent 网格占 40%–97%。竖屏：作者与总调度并排在舞台顶部，网格在下面。
- 网格行列数按「格子最大」自动选，21 个在 1280×720 下是 7×3，在 390×844 下是 3×7 或 4×6。
- **气泡面积和 token 数成正比**，子 agent 与总调度用同一把尺：最大那个子 agent 的峰值对应格子允许的最大半径。这样总调度的气泡（它自己的上下文）能和子 agent 直接比。
- 报告包裹画成固定大小的小亮点，旁边写字数。token 与字数单位不同，不按面积比。
- 结尾把 21 个子 agent 的峰值加起来画成一个大圆，和总调度的圆放在一起。

## 6. 动效时长（以播放秒计，与真实时间无关）

派出飞行 0.9；压扁 0.6；交回飞行 0.9；工具火花 0.7；任务飞入 1.0；回复飞出 1.2。

播放不是匀速的。每条字幕出现时进入慢放，停够读完它的时间：按每秒 8 个字算，最少 2.5 秒，最多 8 秒，所以一条字幕不超过 64 个字；下一条字幕离得太近时，这一段放得更慢。其余时间快进，让整段回放的长度等于选定的播放时长（90 或 180 秒，误差 10% 以内）。慢放时右上角的时钟前面标「慢放」，时钟本身始终显示真实时间。最初按匀速 45 倍播放，开头 30 秒录帧里「作者丢来一句话」只停 0.34 秒，「第一份报告回来了」只停 0.76 秒，所以改成这样。

## 7. 性能预算

Canvas 2D，无依赖。目标：2020 年以后的手机 Safari / Chrome 与桌面 Chrome 60 fps；同屏火花不超过 160 个；单帧绘制在桌面 Chrome 下 < 4 ms。

## 8. 固定机位

| URL | 状态 |
|---|---|
| `?view=hero` | 暂停在同时在跑的子 agent 最多的时刻 |
| `?view=wide` | 暂停在真实时长 60% 处（本数据集里核查与复核两条线叠在一起） |
| `?view=end` | 暂停在结尾总结 |
| `?t=<秒>` | 暂停在真实时间第几秒 |
| `?d=<slug>` | 选数据集，默认第一个 |

钩子 `window.__replay`：`ready`、`seek(t)`（真实秒数）、`play()`、`pause()`、`setPlayback(秒)`、`state()`、`drawStats()`。

## 9. 验收条目

1. 数据文件通过格式检查：每个执行者 `dispatchT ≤ startT ≤ handbackT ≤ duration`，`peakTokens` 等于 `ctx` 最大值，`toolCount` 等于 `tools` 条数。（Node 测试）
2. 隐私：数据文件里没有路径、链接、`.md`、tool id，标签不超过 20 字。（Node 测试）
3. 回放终点：已派出数 = 已交回数 = 执行者总数，已交回报告字数 = 各报告字数之和；任意时刻在跑数不超过数据里的真实最大并发。（Node 测试，逐秒采样）
4. 每个执行者的阶段只往前走：待派 → 派出中 → 工作 → 压扁 → 飞回 → 完成。（Node 测试，逐秒采样）
5. 气泡面积与 token 成正比，误差 < 1%。（Node 测试）
6. 版面：六种视口（1280×720、1920×1080、390×844、844×390、720×800、540×960）下格子都在舞台内、互不重叠；作者与总调度的圆（取总调度最大时）不压格子、不出舞台；格子最大半径 ≥ 14 px，标签字号 ≥ 11 px；结尾大圆放得下。（Node 测试）
7. 同屏火花任意时刻 ≤ 160。（Node 测试，逐秒采样）
8. 字幕占位全部填上，不留 `{`；每条字幕在 90 与 180 秒两档下都停够阅读时间；回放总长与选定时长相差不超过 10%，慢放占比低于 75%。（Node 测试）
9. 三个固定机位在桌面与手机尺寸下截图：无页面错误、无外部请求、画布非空白、字幕与计数可读。（浏览器检查，手动跑）
10. 正常入口录开头 30 秒：任务飞进总调度、第一批派出、气泡开始鼓起都在 30 秒内出现。（浏览器检查，手动跑，逐帧看）
