# 派活回放 · 一页规格

## 1. 体验一句话

访客看一段默认 90 秒的动画，回放一次真实的 Claude Code 工作：作者丢来一句任务，总调度把活拆开派给一群子 agent；每个子 agent 在自己独立的上下文里搜网页、读网页、写核查表，读得越多，它那个小星系越大；干完以后星系坍缩成一颗彗星飞回来，带回的只有几百字的报告。总调度收齐后写一份总结交还作者。要的感受是「原来 AI 是这样分工的」，以及「读了那么多，交回这么少」的那一下。

核心操作是看。可以暂停、拖时间轴、换播放速度，点一个子 agent 看它自己的数字。

现在有两份回放，右上角切换：10-22 的事实核查（21 个子 agent），10-21 做短片「英歌小戏台」的第一段（8 个子 agent，另有 8 次外部 AI Codex 生图）。第二份多出来的感受是「外部 AI 是个黑箱」：会话记录里只看得到派出去、拿回来和用了多久，所以画成黑洞：中心纯黑，只看得到吸积盘和往里掉的尘，不画星系。

画面是一片星空（第三版，2026-10-23）：

- 总调度是中间的恒星，大小按它自己的上下文 token，带日冕；上下文压缩时打一圈冲击波。
- 子 agent 是绕恒星的小星系，光晕面积按 token、星尘随 token 变多，一直在转；它的工具调用是落进星系的光点，按工具类别着色。
- 外部 AI 是黑洞，固定大小。
- 派出是从恒星射出的一颗种子，到位后出现锁定框；交回是星系坍缩成彗星飞回恒星，旁边写字数。
- 作者是左上角的十字星；右上角大号读数是「正在读的上下文」，即此刻所有在跑执行者的上下文之和。
- 背景是星空和星云，两份回放按题材各用一套配色（第 4 节）。
- 结尾把所有子 agent 的峰值加起来画成一个大星系，和总调度的恒星放在一起。

第一版是平面气泡；第二版试过赛博 HUD（青橙线框、网格、扫描线、刻度环），作者看了说两份「形式一样，颜色和形式还是不够炫酷」，只换颜色没换形式，没上线。

## 2. 美学与场地

- 主美学：叙事（一件事从头到尾怎么被分掉、收回来），辅以感官（星系长大、坍缩、彗星飞回）。
- 弧型，看一遍：验的是没看过的人看完能不能复述「总调度派活 → 子 agent 各读很多 → 只交回很少 → 总调度合成」，不验通关率。
- 场地：手机竖屏和电脑横屏各占一半；多半静音，页面不出声；一次看一到两分钟。静音也要看得懂，所以每个关键时刻配一句字幕。

## 3. 数据与隐私

- 数据来自作者本机的 Claude Code 会话记录，由 `tools/extract.py` 抽成 `data/<slug>.js`，页面只读这份。
- 抽出来的只有：任务标签（任务说明里的简短 description）、模型名、工具类别（网页 / 文件 / 写入 / 命令 / 外部工具 / 其他）、时间（相对开始的秒数）、token 数、字数。不带任何提示词原文、报告原文、文件路径、工具参数。
- 任务那句话与字幕都是手写的，不从会话里复制。
- 本仓公开，推上 main 即上线：测试里有一条断言扫数据文件，不得出现路径、链接、`.md` 文件名、tool id。

数据格式（`schema: 1`）：

| 字段 | 含义 |
|---|---|
| `duration` | 回放窗口长度，秒 |
| `task` | `{t, text}`：作者发任务的时刻与手写的一句话 |
| `main.ctx` / `main.tools` | 总调度每轮的上下文 token `[t, n]`；它自己的工具调用 `[t, 类别]` |
| `agents[]` | 每个被派出去的执行者：`id`、`label`、`kind`（`subagent` / `external`）、`vendor`（`claude` / `kimi` / `agy` / `grok` / `gpt`）、`family`（模型族）、`dispatchT`、`startT`、`endT`、`handbackT`、`promptChars`、`handbackChars`（它自己写的报告字数，不含系统外框）、`ctx`、`tools`、`peakTokens`、`toolCount` |
| `reply` | `{t, chars}`：总调度交还作者的那条回复 |
| `captions` | `[[t, 文字], …]`，文字里可用 `{peak:ID}` `{report:ID}` `{reply}` `{sumPeak}` `{sumReport}` `{n}` 占位，播放时按数据填 |

`kind: external` 的执行者（Codex、Kimi、Gemini、Grok 等外部 AI）在会话记录里看不到内部过程：`ctx` 与 `tools` 为空、没有 `peakTokens`，页面把它画成黑洞，只显示派出、交回和用时，不编星系。字段的取法：

- **认调用**：只认总调度的 shell 命令里处在命令位置的包装脚本（`codex-image-gen.ts`、`codex-run.sh`、`kimi-run.sh`、`agy-gui-run.sh`、`gemini-image-gen.ts`、`grok-clean.sh`、`grok-image-gen.sh`），先删掉 heredoc 正文（那里是提示词，常常提到这些名字），`for P in B C; do … done` 这种循环按次数拆开。grep、cat、写文档时提到名字都不算。
- **派出** `dispatchT`：启动命令那一刻；`startT` 同它。
- **交回** `handbackT` 与 **字数** `handbackChars` 按启动方式分三种：前台跑完的，取这条命令自己的结果；`run_in_background` 的，取后台任务完成通知那一刻，字数取通知之后第一次读它结果的那一步的输出长度（认任务输出文件、任务 ID，以及启动命令里 `--output` 和 `>` 重定向写到的文件；那一步若顺手读了别的也一起算，偏多不偏少）；`nohup … &` 挂出去的，取之后第一次出现这次 `--output` 文件的一行 JSON 状态（`{"status": …, "path": …}`）的那一步，字数就是这一行。三种都找不到就让抽取脚本报错停下，不猜。
- **自己跑完** `endT`：只有状态行里带 `elapsed_seconds` 时才有（启动时刻加它），否则为空。总调度往往隔几分钟才去看，所以它和交回时间会差开，详情卡里两个都给。
- **标签**：外部 AI 没有任务说明，标签用 `--external-labels` 按启动顺序手写；不给就用「Kimi 1」这类默认名。

字幕占位另有 `{nSub}`（子 agent 数）、`{nExt}`（外部 AI 调用次数）、`{mainPeak}`（总调度自己的上下文峰值）。

### 回放哪一段（10-21 英歌小戏台）

这次会话从 UTC 04:10 到 10:19 约 6 小时，其实是三段活：

1. 04:10–06:47：作者用 `/goal` 交代做一支 70 秒竖屏短片，静帧和预演各等 30 分钟、没回就往下；作者全程没说话，总调度自己做到出完工报告（3,877 字）。
2. 06:48–09:35：作者回来看片，9 次问答，主要是改配乐，配乐定下后重出正式版。
3. 09:35–10:19：收工，核对经验有没有记到该去的地方。

19 个执行者里 16 个（8 个子 agent、全部 8 次 Codex 生图）在第一段，第二段只有 1 个、第三段 2 个。作者在会话里的发言按 15 条算：`/goal` 1 条、打字 5 条、回答提问 9 条，后 14 条全在第二、三段。

选第一段，不扩展成多轮任务。理由：第一段本身就是一个完整的「派活 → 交回 → 交还作者」，派活最密，外部 AI 全在里面，现有格式（一条任务、一条回复）不用改；第二、三段主要是作者和总调度来回对话，页面画的是派活，对话画不出来，为 3 个执行者去加多条任务、多条回复、分轮计数和分轮总结，改动面大、收获小。没放进来的两段写在结尾字幕里。抽取窗口取 04:10:40 到 06:47:30（完工报告在 06:47:25，停止钩子的反馈在 06:47:36）。

## 5. 构图

- 顶栏：横屏 60 px，竖屏 56 px，矮横屏（高 < 520）44 px；窄竖屏（宽 < 560）且有选择框时分两行、74 px，不显示副标题。底栏：横屏 96 px，竖屏 108 px，窄竖屏 86 px（计数只留一行），矮横屏 74 px，放计数和时间轴。中间是舞台，舞台底部留一条字幕带。
- 恒星和执行者的排法在四种里找「执行者半径最大」的一种：恒星居中、执行者绕整圈轨道；恒星在左、执行者向右扇开；恒星在上、执行者向下扇开；恒星在旁、执行者排成方阵。轨道最多 ⌈n/6⌉ 圈。扇形要比整圈的半径大 1.2 倍才选，方阵要大 1.67 倍；而且只要有一种轨道排法能让执行者半径达到 14 px，就不用方阵，方阵只给手机横屏和扣掉浏览器栏的矮竖屏兜底。实测两份数据：1280×720、1920×1080、720×800、540×960、412×700 是整圈；390×844 和 393×800 下事实核查是右扇、英歌是整圈；844×390、844×340、390×664 是方阵。
- 作者在左上角；右上角是大号读数，矮横屏不显示（计数行里有同样的数）。排法要避开这两处和恒星的两行标签。
- 手机宽度（宽 < 430）和矮屏（竖屏高 < 740、横屏高 < 520）每个执行者只留一行标签，数字在详情卡里。
- **星系光晕面积和 token 数成正比**，子 agent 与总调度用同一把尺：最大那个子 agent 的峰值对应排法允许的最大半径，恒星的半径按它自己的上下文算，日冕和冲击波画在圆外 14 px 以内。总调度的上下文只在压缩那一刻骤降，压缩前保持旧值，不在两次采样之间插值往下滑。
- 交回的报告是固定大小的彗星，旁边写字数。token 与字数单位不同，不按面积比。
- 外部 AI 是黑洞，半径固定为执行者最大半径的一半，不按任何数字缩放。
- 结尾把所有子 agent（不含外部 AI，它们没有 token 数）的峰值加起来画成一个大星系，和总调度的恒星同一把尺放在一起。

## 6. 动效时长（以播放秒计，与真实时间无关）

派出飞行 0.9；坍缩 0.6；彗星飞回 0.9；工具光点 0.7；任务飞入 1.0；回复飞出 1.2；结尾淡入 1.6。

播放不是匀速的。每条字幕出现时进入慢放，停够读完它的时间：按每秒 8 个字算，最少 2.5 秒，最多 8 秒，所以一条字幕不超过 64 个字；下一条字幕离得太近时，这一段放得更慢。其余时间快进，让整段回放的长度等于选定的播放时长（90 或 180 秒，误差 10% 以内）。慢放时右上角的时钟前面标「慢放」，时钟本身始终显示真实时间。最初按匀速 45 倍播放，开头 30 秒录帧里「作者丢来一句话」只停 0.34 秒，「第一份报告回来了」只停 0.76 秒，所以改成这样。

## 7. 性能预算

Canvas 2D，无依赖。目标：2020 年以后的手机 Safari / Chrome 与桌面 Chrome 60 fps；同屏工具光点不超过 160 个；单帧绘制在桌面 Chrome 下 < 4 ms。

## 8. 固定机位

| URL | 状态 |
|---|---|
| `?view=hero` | 暂停在同时在跑的子 agent 最多的时刻 |
| `?view=wide` | 暂停在真实时长 60% 处（本数据集里核查与复核两条线叠在一起） |
| `?view=end` | 暂停在结尾总结 |
| `?t=<秒>` | 暂停在真实时间第几秒 |
| `?d=<slug>` | 选数据集，默认第一个 |

钩子 `window.__replay`：`ready`、`seek(t)`（真实秒数）、`play()`、`pause()`、`setPlayback(秒)`、`tick(dt)`（录制用：先把页面的 `requestAnimationFrame` 换成空函数，再由脚本每帧调一次，`dt` 是播放秒）、`state()`（含 `timeline` `play` `cells` `orbit` `readout`）、`drawStats()`。逐帧截图时每帧先等约 12 ms 再截，否则网页文字层（字幕、计数、总结）会随机缺帧。

## 9. 验收条目

1. 数据文件通过格式检查：每个执行者 `dispatchT ≤ startT ≤ handbackT ≤ duration`，`peakTokens` 等于 `ctx` 最大值，`toolCount` 等于 `tools` 条数；外部 AI 的 vendor 在配色表里，没有 `ctx`、`tools`、`peakTokens`，`endT` 若有则落在派出与交回之间。（Node 测试，遍历 `data/index.js` 里的每份数据）
2. 隐私：数据文件里没有路径、链接、`.md` 和图片、文本、日志、脚本这类文件名、tool id，标签不超过 20 字。（Node 测试）
3. 回放终点：已派出数 = 已交回数 = 执行者总数，已交回报告字数 = 各报告字数之和；任意时刻在跑数不超过数据里的真实最大并发。（Node 测试，逐秒采样）
4. 每个执行者的阶段只往前走：待派 → 派出中 → 工作 → 压扁 → 飞回 → 完成。（Node 测试，逐秒采样）
5. 星系光晕面积与 token 成正比，误差 < 1%。（Node 测试）
6. 版面：九种视口（1280×720、1920×1080、390×844、844×390、720×800、540×960，加上扣掉浏览器栏的手机 390×664、412×700、844×340）下执行者都在舞台内、互不重叠；作者、恒星（取总调度最大时，连日冕和两行标签的宽度）不压执行者、不出舞台；右上角大读数不压执行者；执行者最大半径 ≥ 14 px，标签字号 ≥ 11 px；结尾大星系放得下。（Node 测试）
7. 同屏工具光点任意时刻 ≤ 160。（Node 测试，逐秒采样）
8. 字幕占位全部填上，不留 `{`；每条字幕在 90 与 180 秒两档下都停够阅读时间；回放总长与选定时长相差不超过 10%，慢放占比低于 75%。（Node 测试）
9. 每份数据的三个固定机位在八种尺寸（1280×720、1920×1080、390×844、844×390、720×800、390×664、412×700、844×340）下截图：无页面错误、无外部请求、画布非空白、字幕与计数可读、顶栏不溢出、选择框看得见。（浏览器检查，手动跑）
10. 每份数据从正常入口录开头 30 秒：任务字幕 2 秒内出现，第一次派出和长大的星系在 30 秒内出现。（浏览器检查，手动跑，逐帧看）
11. 外部 AI 和子 agent 分得开：hero 画面里正在工作的黑洞中心像素最亮的通道 < 40，子 agent 星系中心 > 150。选择框能从第一份切到第二份，切过去自动开播。（浏览器检查，手动跑；另逐张看截图）
12. 每套配色都给全了模型族、外部 AI 和工具类别的颜色，`data/index.js` 里写的 `theme` 都存在。（Node 测试）
